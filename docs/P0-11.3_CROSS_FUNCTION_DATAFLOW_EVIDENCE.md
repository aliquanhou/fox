## 0. 架构定位

P0-11.2.7 回答了"谁调用谁"。P0-11.3 回答"调用之间传了什么数据"：

```
SSA CallStmt
  ├─ arguments[i]  ──► ArgumentFlow  (caller -> callee)
  └─ behavior      ──► ReturnFlow     (callee -> caller)
```

仍是 Evidence Layer：只分类已有 SSA 事实，不猜业务语义、不命名函数。

## 2. 真实数据结构

```rust
pub enum FlowKind { ArgumentFlow, ReturnFlow }
pub enum ArgumentSourceKind { Constant, Register, MemoryLoad, Computed, Unknown }
pub enum ReturnConsumerKind { Condition, Instruction{op}, NoConsumer }

pub struct DataFlowEdge {
    caller: u64,
    callee: CallTarget,
    callsite: u64,
    kind: FlowKind,
    detail: FlowDetail,   // Argument{index,source} | Return{consumer}
}

pub struct CrossFunctionDataFlowGraph { edges, outgoing }
```

### Builder Pipeline
```
DecompilerCallGraph (P0-11.2.7, 复用，不重扫 call 关系)
  +
SSA CallStmt.arguments   ─► ArgumentFlow edges (per arg)
SSA CallStmt.behavior    ─► ReturnFlow edge   (per call)
  │
  └─ 递归遍历 If/GuardClause + LiftedCall
  ▼
CrossFunctionDataFlowGraph
```

### Query API
- `edge_count()` / `argument_count()` / `return_count()`
- `flows_of(caller)` / `caller_count()`
- `argument_source_counts()` → (const, reg, mem, computed, unknown)

## 6. Fail-Closed

- 无 data-flow 的函数**不输出**证据块（leaf 保持沉默）
- Unknown call 目标保留为 `call_unknown`，参数未恢复则不产生 edge（不猜）
- emitter 只 `set_dataflow()` 后读取，不自己分析
- 无业务命名、无类型断言

---

## 7. 已知 GAP

1. **mem=0**：当前 PUSH [mem] 参数在 expression 层尚未统一识别为 `Load`（global load 走 P0-8 另一通道），下一阶段接线。
2. **ArgumentFlow 只统计数量**，未输出每个参数到 callee 形式参数的绑定（需 P0-12 签名恢复）。
3. **跨 call 的 return→local 传播**（call result 写入哪个局部变量）尚未追踪，本阶段只到 consumer 类别。
4. stack 上的参数槽位（stdcall/cdecl）未建模。
