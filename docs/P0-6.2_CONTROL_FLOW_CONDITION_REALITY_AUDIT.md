## Executive Summary

本审计使用 NtcMach.exe 真实函数、真实指令地址、真实 CFG/SSA/IR 数据，验证 FOX 从机器码恢复 C-like 条件与控制结构的基础能力。

**核心结论**: FOX 当前**无法**完成 CMP/TEST → FLAGS SSA → Jcc 的完整 Evidence Chain。存在两个 P0 级 GAP 和三个 P1 级 GAP。第一个可读 C-like Dogfood 候选函数已确定（0x401390），但需要先修复 FLAGS 版本化和 CondJump 条件码两个基础问题。

| 核心问题 | 结论 |
|---|---|
| CMP/TEST → FLAGS SSA → Jcc 可追溯 | **FAIL** (FLAGS 未版本化) |
| Jcc → C-like condition 所需信息 | **NO** (条件码在 IR 层丢失) |
| CFG + Dominator 恢复 if/else | **PARTIAL** (无 post-dominator) |
| CFG + Dominator 恢复 loop | **PARTIAL** (无 back edge 标注) |
| switch 恢复 | **NO** (Jump Table Recovery 仅 x64) |

## 一、FLAGS Reality Audit

### 1.1 IR 层 FLAGS 表示

FOX IR (L1) 中 FLAGS 作为 `IROperand::Flags { access: OperandAccess }` 存在。

真实证据（NtcMach 0x401390, `fox ir` 输出）:

```
0x4013B3: Test  Register(ecx, Read), Register(ecx, Read), Flags { access: Write }
0x4013B5: CondJump  Immediate(10), Flags { access: Read }
```

IR 层**正确区分**了 FLAGS 的 Write (CMP/TEST) 和 Read (Jcc) 语义。

### 1.2 SSA 层 FLAGS 版本化 — P0 GAP

**问题**: SSA 构造时，`IROperand::Flags` 匹配分支**忽略 access 字段**，总是使用当前版本（Read 语义）。

代码位置: `crates/fox-analysis/src/ssa/mod.rs`

**Proper 构造路径 (line 549-558)**:
```rust
IROperand::Flags { .. } => {
    let cur_ver = version_stack.get("FLAGS")
        .and_then(|s| s.last().copied())
        .unwrap_or(0);
    ssa_operands.push(SSAOperand::Variable {
        name: "FLAGS".to_string(),
        version: cur_ver,   // ← 总是当前版本，不检查 access
    });
}
```

**简化路径 (line 216-221)**:
```rust
IROperand::Flags { .. } => {
    ssa_operands.push(SSAOperand::Variable {
        name: "FLAGS".to_string(),
        version: 0,          // ← 永远是 version 0
    });
}
```

**后果**:
- `Test @ 0x4013B3` (FLAGS Write) 不分配新 FLAGS 版本
- `CondJump @ 0x4013B5` (FLAGS Read) 使用与 Test 相同的版本
- CMP 和 Jcc 之间**无法建立 use-def 链**
- 多个 CMP 之间的 FLAGS 版本无法区分
- Arithmetic 指令 (ADD/SUB/AND/OR/XOR/SHL/SHR/SAR) 写 FLAGS 同样不版本化

**Evidence Chain 断裂**:
```
CMP @ 0x4013B3  →  FLAGS version N (Write, 但不分配新版本)
                       ↓
Jcc @ 0x4013B5  →  FLAGS version N (Read, 同一个版本)
                       ↓
                 无法区分是哪个 CMP 产生的 FLAGS
```

### 1.3 CMP / TEST / Arithmetic FLAGS 统计

| 指令类型 | IR FLAGS access | SSA 版本化 | 可追溯 |
|---|---|---|---|
| CMP | Write | ❌ 否 | ❌ |
| TEST | Write | ❌ 否 | ❌ |
| ADD/SUB | Write | ❌ 否 | ❌ |
| INC/DEC | Write | ❌ 否 | ❌ |
| AND/OR/XOR | Write | ❌ 否 | ❌ |
| SHL/SHR/SAR | Write | ❌ 否 | ❌ |
| Jcc (所有) | Read | ❌ 用当前版本 | ❌ |

**结论**: FLAGS SSA 版本化完全缺失。这是 P0 级 GAP——没有它，CMP→FLAGS→Jcc 的 Evidence Chain 无法建立。

## 二、Jcc Reality Audit

### 2.1 IR 层条件码丢失 — P0 GAP

**问题**: 所有条件跳转指令在 IR 层映射到同一个 `IROp::CondJump`，条件码（JZ/JNZ/JL/JG/JA/JB 等）完全丢失。

代码位置: `crates/fox-ir/src/l1.rs:193`
```rust
// Conditional jumps map to CondJump
m if m.starts_with('j') && m != "jmp" && m.len() > 1 => IROp::CondJump,
```

**真实证据** (NtcMach 0x401390):
```
原始: 75 0A  jnz  0x004013C1
IR:   CondJump  Immediate { value: 10 }, Flags { access: Read }
```

`Immediate { value: 10 }` 是跳转偏移量（rel8=0x0A=10），**不是条件码**。IR 无法区分 JNZ 和 JZ。

**后果**:
- 无法从 IR 恢复 `if (x != 0)` vs `if (x == 0)`
- 无法区分 signed (JL/JG) 和 unsigned (JB/JA) 比较
- CondJump 的两个操作数（偏移量 + FLAGS Read）都不包含条件信息
- 原始 mnemonic 保留在 `Instruction.mnemonic` 和 `SSAInstruction.original_mnemonic`，但 IR op 本身不携带

### 2.2 NtcMach 真实 Jcc 分布（抽样）

从已审计的函数中统计:

| 函数 | Jcc 类型 | 数量 |
|---|---|---|
| 0x401390 | JNZ | 2 |
| 0x416260 | JNBE, JNZ, JNB, JZ | 4 |
| 0x432290 | JNBE | 1 |
| 0x455E4C (entry) | JNZ | 1 |
| 0x42CC50 | JZ | 2 |

**CFG 全局统计** (359 函数, 7479 blocks, 12698 edges):
- ConditionalTrue edges: 大量（每个 Jcc 产生一个 True edge）
- ConditionalFalse edges: 大量（每个 Jcc 产生一个 False edge）
- CFG 正确区分了 True/False 边，但边的条件语义未知

**注意**: 完整的全二进制 Jcc  opcode 统计需要遍历所有函数的反汇编，本审计受资源限制未做全量扫描。CFG edge 类型统计证明 Jcc 被正确识别为条件分支，但条件码在 IR 层不可用。

## 三、真实 if / else 分布

### 3.1 候选 1: 0x401390 (Primary Candidate)

**函数**: sub_401390, 114 blocks (CFG), 61+ instructions (IR)
**Reality**: Start=High, Body=High, End=Unknown

**真实 Evidence Chain**:

```
BB0 (0x401390-0x4013B5)
  0x4013B3: test ecx, ecx          ← FLAGS Write
  0x4013B5: jnz  0x4013C1          ← FLAGS Read, CondJump
     ├── True  → BB@0x4013C1 (继续执行)
     └── False → BB@0x4013B7 (early return: xor eax,eax; ret)

BB@0x4013F2
  0x4013F2: test eax, eax          ← FLAGS Write
  0x4013F4: jnz  0x401400          ← FLAGS Read, CondJump
     ├── True  → BB@0x401400 (继续执行)
     └── False → BB@0x4013F6 (early return: xor eax,eax; ret)
```

**结构**: 两个连续的 if (nonzero) { continue } else { return 0; } 模式
**Join block**: 每个 if 的 true 分支继续执行，false 分支返回。无显式 join（early return 模式）。
**FLAGS producer**: test ecx,ecx / test eax,eax（可从反汇编获得，但 SSA 中不可追溯）
**Candidate condition**: `if (ecx != 0)` 和 `if (eax != 0)`

### 3.2 候选 2: 0x416260

**函数**: sub_416260, 17 blocks, 28 edges
**结构**: 包含 switch + if/else 混合

```
0x416282: jnbe 0x4162AF    ← if (unsigned >) goto default
0x41628C: jmp [edx*4+0x416318]  ← switch dispatch
...
0x4162BD: jnz 0x4162C9     ← if (nonzero)
0x4162C7: jmp 0x4162D0     ← else
0x4162D3: jnz 0x4162DC     ← if (nonzero)
0x4162DE: jnb 0x41630E     ← if (unsigned >=)
0x4162E6: jz 0x4162ED      ← if (zero)
```

### 3.3 候选 3: 0x427880

**函数**: sub_427880, 8 blocks, 11 edges
**CFG edge types**: ConditionalFalse=3, ConditionalTrue=3, Fallthrough=1, Return=2
**结构**: 3 个条件分支，2 个 return — 典型 if/else 链

### 3.4 if/else 结构化恢复能力

| 能力 | 状态 | 说明 |
|---|---|---|
| CFG 条件边 (True/False) | ✅ IMPLEMENTED | EdgeKind::ConditionalTrue/False |
| DominatorTree | ✅ IMPLEMENTED | idom + dominance frontier |
| Post-Dominator | ❌ NOT IMPLEMENTED | 无法找到 join block |
| if/else 结构化识别 | ❌ NOT IMPLEMENTED | 无 IfNode / 结构化恢复 |
| 条件表达式恢复 | ❌ NOT IMPLEMENTED | 依赖 FLAGS + CondJump 修复 |

**结论**: if/else 恢复 = **PARTIAL**。CFG 边和 Dominator 已有，但缺 post-dominator 和条件恢复。

## 五、Switch Reality

### 5.1 真实 Switch 样本: 0x416260

```
0x416282: 77 2B          jnbe  0x4162AF        ← bounds check (unsigned >)
0x41628C: FF 24 95 18 63 41 00  jmp [edx*4+0x416318]  ← jump table dispatch
0x416298: EB 1B          jmp   0x4162B5        ← case 0
0x41629F: EB 14          jmp   0x4162B5        ← case 1
0x4162A6: EB 0D          jmp   0x4162B5        ← case 2
0x4162AD: EB 06          jmp   0x4162B5        ← case 3
```

这是典型的 MSVC x86 switch 模式: bounds check + jump table + case targets。

### 5.2 Jump Table Recovery 状态 — P1 GAP

**问题**: FOX 的 Jump Table Recovery 是 **x64-only**。

代码位置: `crates/fox-analysis/src/jump_table.rs:94`
```rust
fn recover_msvc_x64_jump_table(...) -> Option<JumpTable>
```

函数名明确为 `recover_msvc_x64_jump_table`，针对 x64 的 `jmp [reg*scale+disp]` 模式。

**NtcMach (x86) 的结果**:
- CFG 中 0x416260 的 edge type = `IndirectJump=1`
- **不是** `JumpTable` edge
- 跳转表目标未被恢复
- switch 的 case targets 不可用

**x86 vs x64 jump table 差异**:
- x64: `jmp [rip+offset]` 或 `jmp [reg*scale+rip+disp]`，RIP 相对寻址
- x86: `jmp [reg*scale+disp]`，绝对地址寻址（如 `[edx*4+0x416318]`）

**结论**: switch 恢复 = **NO**。Jump Table Recovery 需要扩展支持 x86 绝对寻址模式。

## 六、FLAGS → Condition 可恢复性

### 6.1 当前信息缺口

要从 `cmp eax, 5; jl target` 恢复 `eax < 5`，需要:

| 所需信息 | 当前状态 | 来源 |
|---|---|---|
| CMP 左操作数 | ✅ 可用 | IR operands[0] |
| CMP 右操作数 | ✅ 可用 | IR operands[1] |
| Jcc 条件码 (JL) | ❌ 丢失 | IR CondJump 无条件码 |
| signed/unsigned | ❌ 丢失 | 条件码隐含 (JL=signed, JB=unsigned) |
| FLAGS producer 追溯 | ❌ 不可用 | FLAGS 未版本化 |
| branch target | ✅ 可用 | CFG edge / IR immediate |
| fall-through target | ✅ 可用 | CFG edge |

### 6.2 最小修复路径

```
修复 1: FLAGS SSA 版本化
  IROperand::Flags { access: Write } → 分配新版本
  IROperand::Flags { access: Read } → 使用当前版本
  → CMP→FLAGS→Jcc use-def 链建立

修复 2: CondJump 条件码
  IROp::CondJump → IROp::CondJump { condition: JumpCondition }
  JumpCondition: Eq/NotEq/Lt/Le/Gt/Ge/... (signed/unsigned 区分)
  → 可恢复条件表达式

修复 3: 条件表达式构造
  CMP operands + Jcc condition → Expression (Binary comparison)
  → C-like condition: eax < 5
```

### 6.3 Complex Condition (&& / ||)

当前无法处理。需要:
- 多个 CMP+Jcc 序列的模式识别
- short-circuit 语义恢复
- 这属于 P0-6.3+ 范围，不在最小闭环内

## 十、Architecture Recommendation

### 最小下一施工单元: P0-6.3 — FLAGS & Condition Foundation

**目标**: 让 Primary Candidate (0x401390) 第一次从机器码恢复出可读 C-like if/else。

**施工范围 (严格最小化)**:

1. **FLAGS SSA 版本化** (修复 GAP-P0-1)
   - `IROperand::Flags { access: Write }` → 分配新版本
   - `IROperand::Flags { access: Read }` → 使用当前版本
   - 两条 SSA 构造路径都修改
   - destination_operand_idx 排除 FLAGS (已有)

2. **CondJump 条件码** (修复 GAP-P0-2)
   - `IROp::CondJump` → `IROp::CondJump { condition: JumpCondition }`
   - JumpCondition 枚举: Eq, NotEq, LtSigned, LeSigned, GtSigned, GeSigned, LtUnsigned, LeUnsigned, GtUnsigned, GeUnsigned, Overflow, NotOverflow, Sign, NotSign, Parity, NotParity
   - 从原始 mnemonic 映射 (jz→Eq, jnz→NotEq, jl→LtSigned, jb→LtUnsigned, ...)

3. **条件表达式恢复** (新增)
   - 从 SSA use-def 找到 FLAGS producer (CMP/TEST)
   - CMP operands + Jcc condition → Comparison Expression
   - 集成到 Expression Recovery (新增 Comparison expression type)

4. **if/else 结构化识别 (最小版)**
   - 不做完整控制流结构恢复
   - 仅识别: 一个 CondJump + 两个 successor + 一个 return/fallthrough
   - 输出 if (condition) { ... } else { ... } 的最小结构

**不做**:
- ❌ Post-Dominator (P1, 后续阶段)
- ❌ Loop recovery (P1, 后续阶段)
- ❌ Switch recovery (P1, 后续阶段)
- ❌ Variable recovery
- ❌ AST / C emitter
- ❌ Complex condition (&&/||)
- ❌ 修改 Function Discovery / CFG / Memory SSA

### 验证标准

- 0x401390 的两个 test+jnz 能恢复为 `if (ecx != 0)` 和 `if (eax != 0)`
- FLAGS use-def 链可追溯: Jcc → FLAGS version → CMP/TEST instruction
- CondJump 条件码正确: JNZ→NotEq, JZ→Eq, JL→LtSigned, JB→LtUnsigned
- 既有测试不退化
- NtcMach Dogfood 无 OOM

## 十二、核心问题回答

### Q1: FOX 当前能否从真实 NtcMach 中完成 CMP/TEST → FLAGS SSA → Jcc？

**FAIL**。FLAGS 在 SSA 中未版本化（Write access 被忽略），CMP 和 Jcc 使用相同 FLAGS version，use-def 链无法建立。

### Q2: FOX 当前是否已经具备 Jcc → C-like condition 所需全部信息？

**NO**。CondJump 在 IR 层丢失条件码（所有 Jcc 映射到同一 op），无法区分 JZ/JNZ/JL/JG 等。

### Q3: 当前 CFG + Dominator 是否足以恢复 if/else / loop / switch？

- **if/else**: PARTIAL — CFG 条件边 + DominatorTree 已有，但缺 post-dominator 和条件恢复
