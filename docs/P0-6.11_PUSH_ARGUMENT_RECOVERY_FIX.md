## 根因

`recover_call_arguments()` 对 PUSH 调用了 `recover_definition()`，问"PUSH 定义了什么"。

但 PUSH 定义的是 ESP/栈内存（隐式），`expression.rs:631` 明确返回 `Unknown("Push does not produce a recoverable value")`。

参数恢复应该问"PUSH 的**源操作数**是什么"，用 `recover_use(push, 0)`。

## 修改

**文件：** `structured_ir.rs`（唯一修改文件）

```diff
- self.expr_engine.recover_definition(ssa, block_id, idx)
+ self.expr_engine.recover_use(ssa, block_id, idx, 0)
```

未修改：expression.rs（已封板）、SSA、CallGraph、Memory SSA、Evidence。

## 仍 unresolved 的 1104 个调用

原因分类（推测）：
- indirect call 且无 PUSH（寄存器传参 fastcall/thiscall）
- PUSH 源是复杂 memory 表达式，recover_use 返回 Unknown
- call 前无连续 PUSH（参数通过其他方式传递）
- 登记为后续 GAP，不猜测

## 新 GAP

- **GAP-P0-6.11-REGISTER-ARGS**：fastcall/thiscall 的 ECX/EDX 参数未恢复（无调用约定信息）
- **GAP-P0-6.11-MEMORY-ARGS**：部分 PUSH memory 源操作数恢复为 Unknown

均非阻塞，当前 1654 个参数已显著提升可读性。
