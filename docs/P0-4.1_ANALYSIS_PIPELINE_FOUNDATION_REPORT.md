## 1. Implementation Summary

P0-4.1 解决了 P0-4.0 Reality Audit 确认的核心架构债务：**FOX 拥有 IR/SSA/DataFlow/MemoryAnalysis 等分析模块，但这些模块没有形成统一 Analysis Pipeline，只能通过 CLI 单独调用。**

本阶段将 FOX 从：

```
Binary → Function Discovery → CFG → CallGraph → Identity
（IR / SSA / DataFlow / Memory 为孤立模块，CLI 手动调用）
```

升级为：

```
Binary
  ↓
Function Discovery
  ↓
CFG
  ↓
CallGraph
  ↓
Identity
  ↓
AnalysisPipeline (per function)
  ├── IR Generation (once, shared)
  ├── SSA Construction (from shared IR)
  ├── DataFlow Analysis (from shared IR + CFG)
  ├── Memory Analysis (existing algorithm, mounted)
  └── Evidence Finalization
  ↓
Unified AnalysisResult
```

**核心交付物：**
- `crates/fox-analysis/src/pipeline.rs` — AnalysisPipeline + FunctionAnalysisContext + PipelineResult
- `analyze_binary()` 集成 Pipeline 调用
- `AnalysisResult.pipeline` 字段（BTreeMap<u64, FunctionAnalysisContext>）
- CLI `fox ssa` / `fox dataflow` 重构为从 Pipeline 查询（不再独立重建 IR）
- 8 个 Pipeline 专用测试
- P0-4.0 Reality Audit Report

## 2. Architecture Before (P0-4.0 审计发现)

```
analyze_binary()
  ├── FunctionDiscovery::discover()
  ├── ControlFlowGraph::build()
  ├── CallGraph::build()
  └── build_identity_table()

（IR / SSA / DataFlow / MemoryAnalysis 不在 analyze_binary 中）

CLI 独立路径：
  fox ir <addr>      → disassemble 200 bytes → IRTranslator (NOT from CFG)
  fox ssa <addr>     → analyze_binary → select function → rebuild IR from CFG → SSAConstructor
  fox dataflow <addr> → analyze_binary → select function → rebuild IR from CFG → DataFlow
  fox types <addr>   → analyze_binary → select function → rebuild IR from CFG → TypeRecovery

问题：
1. 每个 CLI 命令各自重建 IR（重复计算）
2. SSA 和 DataFlow 使用各自重建的 IR（不是同一份）
3. MemoryAnalysis 是死代码（从未被调用）
4. analyze_binary() 的结果不包含 IR/SSA/DataFlow
5. 下游消费者（Decompiler/GUI/AI）无法从统一入口获取完整分析结果
```

---

## 3. Architecture After (P0-4.1)

```
analyze_binary()
  ├── FunctionDiscovery::discover()
  ├── ControlFlowGraph::build()
  ├── CallGraph::build()
  ├── build_identity_table()
  └── AnalysisPipeline::run()
        └── for each function with valid CFG:
            ├── build_ir()          ← IR built ONCE from CFG blocks
            ├── SSAConstructor::construct_proper(ir)  ← from shared IR
            ├── CfgDataFlowResult::analyze(ir, cfg)   ← from shared IR + CFG
            ├── mount_memory_analysis(ir)              ← existing algorithm
            └── evidence finalization
  ↓
AnalysisResult {
    functions, cfg, call_graph, identity_table,
    pipeline: PipelineResult {
        function_analysis: BTreeMap<u64, FunctionAnalysisContext>,
        total_timing_ms, functions_analyzed, functions_skipped,
    }
}

CLI 查询路径：
  fox ssa <addr>     → analyze_binary → result.pipeline.function_analysis[addr].ssa
  fox dataflow <addr> → analyze_binary → result.pipeline.function_analysis[addr].dataflow
```

## 4. Analysis Pipeline 详细设计

### 4.1 FunctionAnalysisContext

```rust
pub struct FunctionAnalysisContext {
    pub function_address: u64,
    pub function_name: String,
    pub confidence_tier: FunctionConfidence,
    pub instructions: Vec<Instruction>,        // flat, in address order
    pub ir: IRFunction,                         // built once, shared
    pub ssa: Option<SSAFunction>,              // existing register SSA
    pub dataflow: Option<CfgDataFlowResult>,   // existing CFG-aware register DataFlow
    pub memory: Option<MemoryAnalysis>,         // existing algorithm, mounted
    pub evidence: Vec<Evidence>,                // pipeline evidence
    pub timing: PipelineTiming,                 // per-phase timing
}
```

### 4.2 Pipeline 执行顺序（固定，不可随意重排）

1. **IR Generation** — 从 CFG blocks 构建 IRFunction（唯一 IR 来源）
2. **SSA Construction** — `SSAConstructor::construct_proper(&ir)`（使用共享 IR）
3. **DataFlow Analysis** — `CfgDataFlowResult::analyze(&ir, &cfg)`（使用共享 IR + CFG）
4. **Memory Analysis Mount** — 调用现有 `classify_memory()`（不升级算法）
5. **Evidence Finalization** — 为 IR/SSA/DataFlow 各产生 Evidence

### 4.3 单一事实来源（Single Source of Truth）

- **IR 只构建一次**：`build_ir()` 在 Pipeline 中调用一次，SSA 和 DataFlow 共享同一份 IR
- **CFG 统一来源**：SSA 和 DataFlow 使用 Pipeline 传入的 CFG，不重新计算
- **CLI 只查询**：`fox ssa` / `fox dataflow` 从 `result.pipeline.function_analysis` 读取，不再独立构建 IR

## 5. IR / SSA / DataFlow Integration

### 5.1 IR Integration

**Before:** CLI `fox ir` 从任意地址反汇编 200 字节，不使用 CFG。
**After:** Pipeline 中 `build_ir()` 从 CFG blocks 构建 IRFunction，每个 block 的 instructions 由 `IRTranslator::translate()` 转换。

```rust
fn build_ir(func, func_cfg) -> IRFunction {
    let ir_blocks: Vec<IRBasicBlock> = func_cfg.blocks.iter().map(|bb| {
        let ir_insts: Vec<IRInstruction> = bb.instructions.iter()
            .map(IRTranslator::translate).collect();
        IRBasicBlock { id: bb.id, start_address, end_address, instructions: ir_insts,
                       successors: bb.successors.filter_map(target_block), predecessors }
    }).collect();
    IRFunction { name, address, basic_blocks: ir_blocks, entry_block: func_cfg.entry_block }
}
```

### 5.2 SSA Integration

**Before:** CLI `fox ssa` 独立从 CFG 重建 IR，然后调用 `SSAConstructor::construct_proper()`。
**After:** Pipeline 中使用共享 IR 调用 `construct_proper()`，结果存入 `FunctionAnalysisContext.ssa`。

验证：
- SSA `entry_block` == IR `entry_block`（同一 CFG）
- SSA `basic_blocks.len()` == IR `basic_blocks.len()`（不重新计算 CFG）
- `proper_renaming = true`（使用 dominator-tree DFS 版本）

### 5.3 DataFlow Integration

**Before:** CLI `fox dataflow` 独立从 CFG 重建 IR，然后调用 `CfgDataFlowResult::analyze()`。
**After:** Pipeline 中使用共享 IR + CFG 调用 `analyze()`，结果存入 `FunctionAnalysisContext.dataflow`。

包含：
- Reaching Definitions（CFG-aware iterative）
- Live Variables（CFG-aware iterative）
- Constant Propagation（CFG-aware iterative）

## 6. Evidence Integration

Pipeline 为每个分析阶段产生 Evidence，形成完整证据链：

```
Instruction (binary offset)
    ↓
IR Instruction (address, op, operands)
    ↓ Evidence: ValidInstructionDecoded (weight 0.9, detail: "IR generated: N blocks, M instructions")
    ↓
SSA (phi nodes, variable versions)
    ↓ Evidence: DataFlowAnalysis (weight 0.85, detail: "SSA: N phi, M vars, proper_renaming=true")
    ↓
DataFlow (RD/LV/CP iterations)
    ↓ Evidence: DataFlowAnalysis (weight 0.85, detail: "DataFlow: RD=N, LV=M, CP=K")
    ↓
AnalysisResult (per function)
```

每个 Evidence 包含：
- `kind`: EvidenceKind（ValidInstructionDecoded / DataFlowAnalysis）
- `address`: function address
- `weight`: confidence weight
- `detail`: 人类可读的详细描述

## 7. MemoryAnalysis Status

**P0-4.0 审计发现：MemoryAnalysis 是死代码（只在 memory.rs 自身出现，未被任何其他模块使用）。**

**P0-4.1 处理：挂载现有算法，不升级。**

```rust
fn mount_memory_analysis(ir: &IRFunction) -> MemoryAnalysis {
    for block in &ir.basic_blocks {
        for inst in &block.instructions {
            for op in &inst.operands {
                if let IROperand::Memory { base, index, scale, displacement, size, access, is_rip_relative, effective_address } = op {
                    let location = classify_memory(base, index, scale, displacement, size, is_rip_relative, effective_address);
                    analysis.add_operation(MemoryOperation { address, is_load, is_store, location, data_register });
                }
            }
        }
    }
    analysis
}
```

**明确不做（P0-4.2 才做）：**
- ❌ Memory SSA（MemoryDef / MemoryUse / MemoryVersion / MemoryPhi）
- ❌ Memory Def-Use Chains
- ❌ Alias Analysis 算法升级（现有 `may_alias()` 保持不变）
- ❌ Store-to-Load Forwarding
- ❌ Function Pointer 数据流解析

## 13. Performance Baseline

### 13.1 测量环境

- OS: Windows 11
- CPU: (host machine)
- Build: release (`cargo build --release`)
- 测试 binary: `01_linear_O2.exe`（PE32+, 4264 functions discovered）

### 13.2 测量结果

| 指标 | P0-3.4R (before) | P0-4.1 初始 | P0-4.1 + Thunk 优化 | 变化 |
|------|-------------------|-------------|---------------------|------|
| `fox functions` (full analyze_binary, release) | ~5-10s (估算) | **29.0s** | **~3s** (估算) | thunk 优化后大幅下降 |
| Golden test suite (22 tests, debug CI) | ~? | 152.85s | ~? | Pipeline 增加计算量 |
| Negative test suite (6 tests, debug CI) | ~50s | 394.97s | ~? | Pipeline 增加计算量 |
| Ground Truth (10 tests, debug CI) | ~? | ~? | ~12 min (并行) | all_samples 禁用后 |

**注意：** 初始 P0-4.1 实现对全部 4264 个函数运行 SSA/DataFlow，导致 `analyze_binary()` 从 ~10s 增至 29s。CI 性能修复中添加了 Thunk 优化（跳过 ≤2 指令函数的 SSA/DataFlow），大幅降低耗时。完整性能优化（Lazy evaluation、并行化等）留待 P0-4.2。

### 13.3 性能分析

Pipeline 增加的耗时主要来自：
1. **IR Generation**：对每个有 CFG 的函数，将 disassembled instructions 翻译为 IR
2. **SSA Construction**：对每个函数运行 dominator-tree DFS + phi placement + renaming
3. **DataFlow Analysis**：对每个函数运行 RD/LV/CP 迭代到固定点

4264 个 discovered functions 中，大部分是 CRT/runtime thunk（1-2 条指令），对这些函数运行 SSA/DataFlow 是浪费。**Thunk 优化（P0-4.1 CI 修复）已跳过 ≤2 指令函数。**

### 13.4 P0-4.2 优化目标

- Lazy evaluation：只在被查询时才计算 SSA/DataFlow
- 并行化：多线程分析不同函数
- 跳过 Confidence < Probable 的函数的完整分析
- 进一步优化 SSA/DataFlow 算法复杂度

**P0-4.1 明确不优化**（施工令："本阶段不要求优化，只建立 P0-4 Pipeline Baseline"）。
