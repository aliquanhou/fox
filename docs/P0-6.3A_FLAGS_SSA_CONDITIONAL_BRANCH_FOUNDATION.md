## 1. Executive Summary

P0-6.3A fixes the two P0 GAPs identified in P0-6.2 Reality Audit:

1. **FLAGS SSA dual-model** — `eflags` (from zydis implicit_writes) and `FLAGS` (from IROperand::Flags) were two disconnected variables. FLAGS operands were always v0, breaking CMP→FLAGS→Jcc use-def chains.
2. **CondJump condition code loss** — All Jcc instructions mapped to `IROp::CondJump` (unit variant), losing JZ/JNZ/JL/JG/JA/JB semantic distinction.

Both are fixed with minimal, evidence-first changes. The first real closed loop is demonstrated on NtcMach.exe `0x401390`:

```
TEST @ 0x4013B3  →  FLAGS Write → vN
JNZ  @ 0x4013B5  →  FLAGS Read  → vN  →  Condition: (ecx & ecx) != 0
TEST @ 0x4013F2  →  FLAGS Write → vM
JNZ  @ 0x4013F4  →  FLAGS Read  → vM  →  Condition: (eax & eax) != 0
```

---

## 2. Root Cause Analysis

### 2.1 FLAGS Dual-Model

**Before P0-6.3A:**

```
all_writes() = writes_registers + implicit_writes
                              ↓
              zydis reports EFLAGS as implicit write
                              ↓
              "eflags" enters def_blocks → phi_placement → push_version("eflags")
                              ↓
              variable_versions: eflags: v33  (isolated phi variable)

IROperand::Flags → SSAOperand::Variable { name: "FLAGS", version: 0 }
                              ↓
              "FLAGS" never calls push_version → always v0
                              ↓
              "eflags" ≠ "FLAGS" → no use-def connection
```

**After P0-6.3A:**

```
all_writes() excludes "eflags"/"rflags" from implicit_writes
              + adds "FLAGS" when writes_flags=true
                              ↓
              phi_placement uses "FLAGS" (single identity)

IROperand::Flags { access: Write } → push_version("FLAGS") → new version
IROperand::Flags { access: Read }  → current version
                              ↓
              CMP/TEST → FLAGS def → Jcc use-def chain established
```

### 2.2 CondJump Condition Loss

**Before:** `IROp::CondJump` (unit variant). All Jcc indistinguishable.

**After:** `IROp::CondJump { condition: JumpCondition }`. 16 conditions preserved.

## 5. Evidence Chain

For every recovered condition:

```
Condition
  ← operator: JumpCondition (from original Jcc mnemonic)
  ← left/right: SSA operands from CMP/TEST producer
  ← flags_producer_address: instruction address of CMP/TEST
  ← branch_address: instruction address of Jcc
  ← FLAGS version: use-def chain (Jcc FLAGS Read → CMP/TEST FLAGS Write)
```

No guessing. If use-def fails → `ProducerNotFound`. If producer is not CMP/TEST → `ProducerNotCmpTest`.

---

## 8. Known Limitations / Future GAP

1. **Arithmetic FLAGS producers** — ADD/SUB/AND/OR/XOR/SHL/SHR/SAR also write FLAGS. Condition recovery currently only resolves CMP/TEST producers. These are reported as `ProducerNotCmpTest`, not guessed.
2. **FLAGS is coarse-grained** — All flag bits share one version. Future Flag Bit SSA could version ZF/SF/OF/CF independently, but this is not needed for the first C-like if/else.
3. **Condition operands are raw SSA values** — `eax.v3` not yet mapped to C variable names. This is P0-6.x Variable Recovery.
4. **No AST/source emission** — Condition is a structured internal result, not C code.

## 10. Conclusion

P0-6.3A establishes the minimal, correct, extensible FLAGS SSA Foundation:

- FLAGS is a unified logical SSA state variable (single identity "FLAGS")
- CondJump preserves real condition codes (16 JumpCondition variants)
- CMP/TEST → FLAGS def → Jcc use-def chain is real and traceable
- First real NtcMach condition recovery: 64/64 resolved on 0x401390

**No Evidence, no Claim.** Every condition traces to a real CMP/TEST instruction via SSA use-def.
