## 0. 核心问题

> 现有五个模块（Expression Recovery、Condition Recovery、Control Structure Recovery、Function Reality、Evidence）如何汇聚到一个统一的 Decompiler Structured IR？
> 0x41C9A8、0x41F000、0x401390 分别需要哪些字段？

**简短回答:** 现有模块各自产出独立数据结构，没有统一的"函数级语句列表"概念。需要新建 `structured_ir.rs` 模块，定义 `DecompilerFunction` → `Vec<Statement>`，其中 `Statement` 包含 Assign/If/GuardClause/Return/Call/Unknown。五个模块作为 Consumer 输入，Structured IR 作为统一输出。Unknown 必须是一等语句。

## 1. 现有模块审计

### 1.1 fox-decompiler 当前结构

```
crates/fox-decompiler/src/
├── lib.rs              # 空壳 Decompiler struct，仅 re-export
├── expression.rs       # P0-6.1: Expression Recovery (~1500行)
├── condition.rs        # P0-6.3A: Condition Recovery (~350行)
└── control_structure.rs # P0-6.4B-R: Control Structure (~800行)
```

**关键发现:** `Decompiler` struct 是空的（仅 `new()`），没有任何方法将三个模块的输出统一起来。三个模块各自独立运行，产出互不关联的数据结构。

### 1.2 五个模块的输出

| 模块 | 输出类型 | 关键字段 | 状态 |
|---|---|---|---|
| Expression Recovery | `Expression` enum | Constant, Variable, Binary, Unary, Load, Call, Phi, Unknown | 🔒 SEALED |
| Condition Recovery | `ConditionRecovery` enum | Resolved(Condition), ProducerNotCmpTest, ProducerNotFound, NotConditionalJump | 🔒 SEALED |
| Control Structure | `ControlStructure` enum | IfElse{condition, then, else, merge}, GuardClause{condition, body, return}, Unknown{reason} | 🔒 SEALED |
| Function Reality | `FunctionReality` struct | start, body, end, identity (各有 status/confidence/evidence) | 🔒 SEALED |
| Evidence/Claim | `EvidenceClaim` struct | claim_type, subject, strength, source_evidence | 🔒 SEALED |

### 1.3 现有数据结构的问题

**问题 1: 没有统一的"语句"概念**
- Expression 是表达式（rvalue），不是语句
- ControlStructure 是控制流结构，不包含内部语句
- Condition 是条件表达式，不是完整语句
- 没有 `Assign(lhs, rhs)`、`Return(expr)`、`CallStmt(target, args)` 等语句概念

**问题 2: 没有函数级聚合**
- `recover_all_definitions()` 返回 `Vec<Expression>`（表达式列表，不是语句）
- `recover_control_structures()` 返回 `Vec<ControlStructure>`（控制结构列表）
- `recover_all_conditions()` 返回 `Vec<ConditionRecovery>`（条件列表）
- 没有 `DecompilerFunction { statements: Vec<Statement> }` 将三者统一

**问题 3: 没有嵌套结构**
- IfElse 只记录 block index（then_block, else_block, merge_block），不包含这些块内部的语句
- GuardClause 只记录 body_block 和 return_block，不包含内部语句
- 要输出可读代码，必须将块内的语句嵌套到 If/Guard 结构中

**问题 4: Unknown 不是一等语句**
- `ControlStructure::Unknown` 存在，但它只是控制流分类，不是可以输出的语句
- 需要 `Statement::Unknown { reason, goto_target }` 来表示"无法结构化的控制流"

## 2. 五个模块如何汇聚到 Structured IR

### 2.1 汇聚架构

```
                    ┌─────────────────────┐
                    │   SSAFunction       │
                    │   (fox-analysis)    │
                    └──────────┬──────────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
          ▼                    ▼                    ▼
  ┌───────────────┐   ┌───────────────┐   ┌───────────────────┐
  │ Expression    │   │ Condition     │   │ Control Structure │
  │ Recovery      │   │ Recovery      │   │ Recovery          │
  │ (P0-6.1)      │   │ (P0-6.3A)    │   │ (P0-6.4B-R)      │
  └───────┬───────┘   └───────┬───────┘   └─────────┬─────────┘
          │                    │                       │
          │ Expression         │ Condition             │ ControlStructure
          │ (rvalue)           │ (condition)           │ (flow structure)
          │                    │                       │
          └────────────────────┼───────────────────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │  Structured IR      │
                    │  (NEW: P0-6.6A)    │
                    │                     │
                    │  DecompilerFunction │
                    │  ├── address        │
                    │  ├── name           │
                    │  ├── reality        │ (from FunctionReality)
                    │  └── statements     │
                    │      ├── Assign     │ (from Expression)
                    │      ├── If         │ (from ControlStructure + nested statements)
                    │      ├── GuardClause│ (from ControlStructure + nested statements)
                    │      ├── Return     │ (from Return edge + Expression)
                    │      ├── CallStmt   │ (from Call edge + Expression)
                    │      └── Unknown    │ (from ControlStructure::Unknown)
                    └──────────┬──────────┘
                               │
                               ▼
                    ┌─────────────────────┐
                    │  C-like Emitter     │
                    │  (P0-6.6B, future) │
                    └─────────────────────┘
```

### 2.2 各模块的角色

| 模块 | 在 Structured IR 中的角色 | 提供什么 |
|---|---|---|
| Expression Recovery | 提供 rvalue 表达式 | Assign 的 rhs、Return 的值、Call 的参数、If 条件中的操作数 |
| Condition Recovery | 提供条件表达式 | If/GuardClause 的 condition 字段 |
| Control Structure Recovery | 提供控制流结构骨架 | If/GuardClause/Unknown 的块索引和证据 |
| Function Reality | 提供函数元数据 | 函数的 start/body/end/identity 状态（用于输出注释） |
| Evidence/Claim | 提供可追溯性 | 每个 Statement 的 evidence 字段（指令地址、证据链） |

### 2.3 汇聚的关键算法

**Statement 构建顺序:**
1. 遍历 CFG 块（按地址顺序）
2. 对每个块：
   a. 遍历 SSA 指令，对有 `destination_operand_idx` 的指令生成 `Assign` 语句
   b. 对 Call 指令生成 `CallStmt` 语句
   c. 对 Return 边生成 `Return` 语句
3. 遍历 ControlStructure 列表：
   a. IfElse → 生成 `If` 语句，将 then/else 块内的语句嵌套进去
   b. GuardClause → 生成 `GuardClause` 语句，将 body 块内的语句嵌套进去
   c. Unknown → 生成 `Unknown` 语句（goto 或注释）
4. 按控制流顺序排列顶层语句

**嵌套处理:**
- If/GuardClause 内部包含 `Vec<Statement>`（从对应 CFG 块的语句中提取）
- merge 块的语句放在 If 之后（顶层）
- 不做完整的结构化控制流分析（no Post-Dominator），只做基于块索引的简单嵌套

## 3. 三个目标函数需要的字段

### 3.1 0x41C9A8（极简函数，1 block，6 instrs，100% expr recovery）

**现实:**
- 1 个基本块，无分支，无调用
- 6 条 SSA 指令，3 个有 destination
- 1 条 Return 边

**需要的 Structured IR 字段:**
```
DecompilerFunction {
    address: 0x41C9A8,
    statements: [
        Assign { lhs: Variable("v1"), rhs: Load(...) },     // from SSA inst #1
        Assign { lhs: Variable("v2"), rhs: Binary(Add, ...) }, // from SSA inst #2
        Return { value: Some(Variable("v2")) },               // from Return edge
    ],
}
```

**关键需求:**
- `Assign` 语句（lhs = SSA variable, rhs = Expression）
- `Return` 语句（value = Option<Expression>）
- 线性语句列表，无嵌套

### 3.2 0x41F000（4 blocks，2 cond branches，1 GuardClause + 1 Unknown）

**现实:**
- 4 个基本块
- 2 个条件分支：
  - jz @ 0x41F010 → GuardClause（true→ret, false→continuation）
  - jz @ 0x41F020 → Unknown（双 return）
- 2 个 external call，1 个 indirect call
- Expression Recovery: 3/16 (18.8%)

**需要的 Structured IR 字段:**
```
DecompilerFunction {
    address: 0x41F000,
    statements: [
        // block[0]: prologue + setup
        Assign { ... },
        Assign { ... },

        // jz @ 0x41F010 → GuardClause
        GuardClause {
            condition: ConditionRecovery::Resolved(...),  // from P0-6.3A
            body: [ Assign{...}, CallStmt{...} ],           // block[1] statements
            return_value: Some(...),                         // block[3] return
            evidence: StructureEvidence { ... },
        },

        // jz @ 0x41F020 → Unknown (double return)
        Unknown {
            reason: "both branches return immediately (double return)",
            condition: ConditionRecovery::Resolved(...),
            goto_target: Some(0x41F030),  // or None if cannot determine
            evidence: StructureEvidence { ... },
        },

        // normal path continuation
        CallStmt { target: Indirect, arguments: [...] },
        Return { value: Some(...) },
    ],
}
```

**关键需求:**
- `GuardClause` 语句（condition + body statements + return）
- `Unknown` 语句（reason + condition + optional goto_target）
- `CallStmt` 语句（target + arguments）
- 嵌套语句（GuardClause.body 包含块内语句）
- Evidence 追溯到指令地址

### 3.3 0x401390（114 blocks，627 instrs，46 IfElse + 13 Guard + 5 Unknown）

**现实:**
- 114 个基本块，627 条 SSA 指令
- 64 个条件分支：
  - 46 IfElse（有 merge）
  - 13 GuardClause（early return）
  - 5 Unknown
- Expression Recovery: 134/283 (47.3%)
- 大量嵌套控制流

**需要的 Structured IR 字段:**
```
DecompilerFunction {
    address: 0x401390,
    statements: [
        // 大量 Assign / CallStmt / If / GuardClause / Unknown / Return
        // If 语句嵌套 body statements
        // 总语句数可能 200-400
        // 必须保证不 OOM、不无限递归
    ],
    // 元数据
    reality: FunctionReality { ... },  // from P0-5.6B
    total_statements: N,
    total_unknown: 5,
}
```

**关键需求:**
- 高效的语句构建（O(blocks + instructions)，不指数级）
- 嵌套 If 语句（If.body 包含更多 If/Guard/Assign）
- 大量 Unknown 语句（5个，必须正确输出）
- 资源保护（继承 P0-6.1R 的 function-level budget）
- 不崩溃、不 OOM、不无限递归

## 4. 推荐的 Structured IR 数据模型

### 4.1 模块位置

新建 `crates/fox-decompiler/src/structured_ir.rs`

理由：
- 与 expression/condition/control_structure 并列
- 作为 Consumer 层，读取三个模块的输出
- 不修改现有模块
- lib.rs 中 `pub mod structured_ir;` + re-export

### 4.2 核心数据结构

```rust
/// A decompiled function with structured statements.
pub struct DecompilerFunction {
    /// Function address.
    pub address: u64,
    /// Function name (if known, e.g. from symbols/imports).
    pub name: Option<String>,
    /// Function reality (from P0-5.6B, optional metadata).
    pub reality: Option<FunctionRealityRef>,
    /// Top-level statements in control-flow order.
    pub statements: Vec<Statement>,
    /// Evidence for the function as a whole.
    pub evidence: FunctionEvidence,
}

/// A single structured statement.
pub enum Statement {
    /// Assignment: lhs = rhs
    Assign {
        lhs: AssignTarget,
        rhs: Expression,
        evidence: StatementEvidence,
    },
    /// if (condition) { then } else { else } [→ merge]
    If {
        condition: ConditionRecovery,
        then_body: Vec<Statement>,
        else_body: Vec<Statement>,
        merge_block: Option<usize>,
        evidence: StatementEvidence,
    },
    /// if (condition) { return ... };  // guard clause / early return
    GuardClause {
        condition: ConditionRecovery,
        body: Vec<Statement>,
        return_value: Option<Expression>,
        evidence: StatementEvidence,
    },
    /// return [value];
    Return {
        value: Option<Expression>,
        evidence: StatementEvidence,
    },
    /// call target(args);  // as a statement (return value ignored)
    CallStmt {
        target: CallTarget,
        arguments: Vec<Expression>,
        evidence: StatementEvidence,
    },
    /// Unstructured control flow: /* reason */ goto target;
    Unknown {
        reason: String,
        condition: Option<ConditionRecovery>,
        goto_target: Option<u64>,
        evidence: StatementEvidence,
    },
    /// Phi node assignment (SSA phi, may be elided by emitter)
    PhiAssign {
        lhs: AssignTarget,
        incoming: Vec<PhiIncoming>,
        evidence: StatementEvidence,
    },
}

/// Assignment target.
pub enum AssignTarget {
    /// SSA variable (register with version).
    Variable { name: String, version: u32 },
    /// Memory location (stack offset, etc.).
    Memory { address: Box<Expression> },
    /// Unknown / not recoverable.
    Unknown,
}

/// Evidence for a single statement.
pub struct StatementEvidence {
    /// Source instruction addresses (may be multiple for aggregated statements).
    pub instruction_addresses: Vec<u64>,
    /// Source CFG block IDs.
    pub block_ids: Vec<usize>,
    /// Human-readable detection rationale.
    pub reason: String,
}

/// Evidence for the function as a whole.
pub struct FunctionEvidence {
    /// Number of SSA instructions processed.
    pub ssa_instructions: usize,
    /// Number of CFG blocks processed.
    pub cfg_blocks: usize,
    /// Number of control structures recovered.
    pub control_structures: usize,
    /// Number of unknown/unstructured statements.
    pub unknown_statements: usize,
}
```

### 4.3 设计原则

1. **Unknown 是一等语句** — `Statement::Unknown` 可以输出 `/* reason */ goto target;`，不编造 if
2. **Evidence 可追溯** — 每个 Statement 都有 `StatementEvidence`，包含指令地址和块 ID
3. **嵌套但不过度** — If/GuardClause 内部包含 `Vec<Statement>`，但不做完整结构化分析（no Post-Dominator）
4. **不修改现有模块** — Structured IR 是纯 Consumer，读取 expression/condition/control_structure 的输出
5. **资源保护** — 继承 P0-6.1R 的 function-level budget，语句数量有上限
6. **Placeholder 变量诚实标注** — `AssignTarget::Variable { name, version }` 明确是 SSA 变量，不伪装成"真实恢复变量"

### 4.4 构建算法（高层）

```
fn build_structured_ir(cfg, ssa, control_structures) -> DecompilerFunction {
    // Phase 1: Build flat statement list per CFG block
    let block_statements: HashMap<block_id, Vec<Statement>> = {};
    for block in cfg.blocks {
        let mut stmts = vec![];
        for (idx, inst) in ssa.block(block).instructions.iter().enumerate() {
            if inst.op == "Call" {
                stmts.push(CallStmt { ... });
            } else if inst.destination_operand_idx.is_some() {
                let expr = ExpressionRecovery::recover_definition(ssa, block.id, idx);
                stmts.push(Assign { lhs: ..., rhs: expr, ... });
            }
        }
        if block.has_return_edge() {
            let ret_val = ExpressionRecovery::recover_return_value(ssa);
            stmts.push(Return { value: ret_val, ... });
        }
        block_statements.insert(block.id, stmts);
    }

    // Phase 2: Lift control structures, nesting block statements
    let mut top_level: Vec<Statement> = vec![];
    let mut processed_blocks: HashSet<block_id> = {};

    for cs in control_structures {
        match cs {
            IfElse { then_block, else_block, merge_block, ... } => {
                let then_body = block_statements.remove(then_block);
                let else_body = block_statements.remove(else_block);
                top_level.push(If { then_body, else_body, ... });
                processed_blocks.insert(then_block);
                processed_blocks.insert(else_block);
                // merge_block statements stay in top_level (added in Phase 3)
            }
            GuardClause { body_block, return_block, ... } => {
                let body = block_statements.remove(body_block);
                let return_value = extract_return_value(return_block);
                top_level.push(GuardClause { body, return_value, ... });
                processed_blocks.insert(body_block);
                processed_blocks.insert(return_block);
            }
            Unknown { branch_block, ... } => {
                top_level.push(Unknown { ... });
                // branch targets may still have statements (added in Phase 3)
            }
        }
    }

    // Phase 3: Add remaining block statements in address order
    for block in cfg.blocks.sort_by(start_address) {
        if !processed_blocks.contains(&block.id) {
            if let Some(stmts) = block_statements.get(&block.id) {
                top_level.extend(stmts.clone());
            }
        }
    }

    DecompilerFunction { statements: top_level, ... }
}
```

## 5. 与现有模块的兼容性

### 5.1 不修改现有模块

- `expression.rs` — 不修改，直接调用 `ExpressionRecovery::recover_definition()`
- `condition.rs` — 不修改，直接使用 `ConditionRecovery` 枚举
- `control_structure.rs` — 不修改，直接使用 `ControlStructure` 枚举
- `lib.rs` — 仅新增 `pub mod structured_ir;` + re-export

### 5.2 向后兼容

- 现有 API（`recover_control_structures`, `recover_condition`, `ExpressionRecovery`）不变
- Structured IR 是新增层，不替换现有模块
- 旧代码继续使用现有模块，新代码可以使用 Structured IR

### 5.3 序列化

- `DecompilerFunction` 和 `Statement` 应 derive `Serialize/Deserialize`
- 与现有 JSON 输出风格一致
- 不破坏旧字段

## 6. 风险与限制

### 6.1 已知限制

1. **不做完整结构化控制流分析** — 没有 Post-Dominator，If/Guard 的嵌套基于块索引，可能不完美
2. **不做 Variable Recovery** — 变量名是 SSA 变量名（`eax.v1`），不是 `arg0`/`local_1`
3. **不做 Type Recovery** — 所有值默认 `int`/`void*`
4. **不做 Call Argument Recovery** — Call 的 arguments 可能为空或不完整
5. **Unknown 可能较多** — 对于非结构化 CFG，Unknown 语句是正常的

### 6.2 风险

1. **嵌套语句可能重复** — 如果一个块同时被 If 和 Guard 引用，需要去重
2. **语句顺序可能不完美** — 基于块地址排序，对于复杂 CFG 可能不是最优顺序
3. **大函数性能** — 0x401390 有 114 blocks / 627 instrs，需要验证构建时间和内存
4. **Expression Unknown 率高** — 复杂函数 47-70% expr recovery，大量 Assign 的 rhs 是 Unknown

### 6.3 缓解措施

1. 块语句使用 `HashMap` 管理，嵌套时 remove（避免重复）
2. 语句顺序先按控制流结构，再按块地址补充
3. 继承 P0-6.1R 的 function-level budget
4. Unknown Expression 正常输出为 `/* unknown */`，不崩溃

## 7. 审计结论

| 项目 | 结果 |
|---|---|
| 现有模块是否统一 | ❌ 三个模块独立产出，无统一语句层 |
| Decompiler struct 是否可用 | ❌ 空壳，无方法 |
| 是否需要新建模块 | ✅ 新建 `structured_ir.rs` |
| Unknown 是否一等语句 | ✅ `Statement::Unknown` |
| Evidence 可追溯性 | ✅ 每个 Statement 有 `StatementEvidence` |
| 是否修改现有模块 | ❌ 纯 Consumer，不修改 |
| 0x41C9A8 所需字段 | Assign + Return（线性） |
| 0x41F000 所需字段 | GuardClause + Unknown + CallStmt + Return（嵌套） |
| 0x401390 所需字段 | 全量 + 大量嵌套 + 资源保护 |

### 推荐下一步

**P0-6.6A Implementation:** 新建 `structured_ir.rs`，实现 `DecompilerFunction` / `Statement` / 构建算法，用 0x41C9A8 做 smoke test，0x41F000 做 control flow test，0x401390 做 scale test。

**不做:** Variable Recovery、Type Recovery、Call Argument Recovery、C-like Emitter（这些是 P0-6.6B 及以后）。
