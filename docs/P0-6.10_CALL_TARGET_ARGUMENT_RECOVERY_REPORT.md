## 一、Executive Summary

P0-6.10 解决了 NtcMach 反编译输出中最影响阅读的问题之一：**几乎所有 call 都显示为 `call_unknown(/* arguments unresolved */)`**。

**根因：** CallGraph 已经完整解析了所有 call target（Direct/External/Indirect，带 resolved_symbol），但 StructuredIRBuilder 完全没有使用它。`extract_call_target()` 只看 SSA operands，而 direct call 的 immediate target 在 SSA 构造中丢失。

**修复：**
1. 从 CallGraph 构建 `call_targets: HashMap<call_instruction_addr, CallTarget>` 映射
2. 通过 `StructuredIRBuilder::with_call_targets()` 传入
3. `extract_call_target()` 优先查映射，fallback 到 SSA operand 解析
4. 新增 `recover_call_arguments()`：从 call 前连续 PUSH 指令恢复栈参数（最多8个），Unknown 表达式自动过滤

**结果（NtcMach.exe 359 函数）：**

|------|-------------|--------------|
| 已知地址 call | 0 | **1437** |

| call_unknown | ~2700+ | **1219**（全部为 indirect unknown，诚实不猜） |

## 三、Root Cause 分析

### 问题 1：CallGraph 数据未被消费
`CallGraph::build()` 已经完整解析每个 call：
- `CallGraphEdge { kind, caller, callee, call_instruction, resolved_symbol, indirect_kind }`
- `classify_call()` 处理 direct call（import thunk → External、IAT → External、func_by_addr → Direct internal）
- indirect call（RIP-relative IAT → External、register/memory/vtable → Indirect）

但 `StructuredIRBuilder::build()` 只接收 `(cfg, ssa, control_structures)`，完全没有 CallGraph 数据。

### 问题 2：SSA 丢失 direct call immediate
`extract_call_target()` 遍历 SSAInstruction.operands 寻找 Label/Constant：
- direct call 的 target 在原始 IR 中是 `IROperand::Immediate { value }`
- SSA 构造后，immediate 可能未保留为 Constant/Label
- 导致几乎所有 call 返回 `CallTarget::Unknown`

## 五、Call Target Recovery 方法

### 数据流程
```
CallGraph (已封板)
    │
    ├── CallGraphEdge.call_instruction (u64)  ← key
    ├── CallGraphEdge.kind (Direct/External/Indirect/Unknown)
    ├── CallGraphEdge.callee (Option<u64>)
    └── CallGraphEdge.resolved_symbol (Option<String>, 如 "kernel32.dll!GetFileSize")
    │
    ▼
HashMap<u64, CallTarget>  (批量测试中构建)
    │
    ├── Direct + callee → CallTarget::Address(addr)
    ├── External + resolved_symbol → CallTarget::Symbol(func_name)  (提取 dll!func 中的 func)
    ├── Indirect + resolved_symbol → CallTarget::Symbol(func_name)
    ├── Indirect + callee → CallTarget::Address(addr)
    └── 其他 → CallTarget::Unknown
    │
    ▼
StructuredIRBuilder.with_call_targets(map)
    │
    ▼
extract_call_target(inst):
    1. self.call_targets.get(&inst.address)  ← 优先
    2. fallback: SSA operand Label/Constant 解析
    3. CallTarget::Unknown
```

### 映射构建代码（批量测试）
```rust
let call_targets: HashMap<u64, CallTarget> = {
    let mut map = HashMap::new();
    for node in &result.call_graph.nodes {
        for edge in &node.outgoing_calls {
            let target = match edge.kind {
                Direct | External => {
                    if let Some(ref sym) = edge.resolved_symbol {
                        CallTarget::Symbol(sym.split('!').last().unwrap_or(sym).to_string())
                    } else if let Some(callee) = edge.callee {
                        CallTarget::Address(callee)
                    } else { CallTarget::Unknown }
                }
                Indirect => { /* same logic */ }
                Unknown => CallTarget::Unknown,
            };
            map.insert(edge.call_instruction, target);
        }
    }
    map
};
// 2995 entries
```

## 六、Call Argument Recovery 方法

### 策略：Evidence-First，只从可靠来源恢复
- **只看 call 前同一块内的连续 PUSH 指令**
- NOP 跳过，非 PUSH 停止
- PUSH 值用 ExpressionRecovery 恢复
- **Unknown 表达式自动过滤**（不假装是参数）
- 最多 8 个参数（防止爆炸）
- `arguments_complete` 标记是否全部恢复

### 为什么只从 PUSH 恢复？
- NtcMach 是 x86 32位 MSVC 编译，cdecl/stdcall 使用栈传参
- PUSH 是最可靠的栈参数证据
- 寄存器参数（ECX/EDX for fastcall/thiscall）需要调用约定信息，当前 FOX 没有 → **登记 GAP，不猜测**
- 不猜参数数量：没有 PUSH 就输出 `/* arguments unresolved */`

### Fail-Closed
- PUSH 值无法恢复 → 过滤掉，不输出假参数
- 超过 8 个 PUSH → 标记 incomplete，输出 `arg1, arg2, ...`
- 间接 call target 不确定 → 参数即使有 PUSH 也只输出到 `call_unknown(arg1, ...)`
