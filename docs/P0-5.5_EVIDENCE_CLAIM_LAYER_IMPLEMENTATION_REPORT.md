## 1. Implementation Summary

P0-5.5 establishes FOX's first **Evidence → Claim semantic layer**. Before this stage, all evidence fed a single scalar confidence number, regardless of what the evidence actually proved. After this stage:

```
Before:  Evidence → confidence → "this is a function"
After:   Evidence → Claim(FunctionStart/Body/End/Identity/...) → Reality
```

**Core principle**: Evidence is not Truth. Evidence supports a specific Claim.

### What was implemented
- `ClaimType` enum (9 variants)
- `ClaimSubject` enum (address-stable, not free-form string)
- `ClaimStrength` enum (Strong/Supporting/Contextual/Negative/Unknown)
- `EvidenceClaim` struct (claim_type + subject + strength + source_evidence)
- `Evidence.claim: Option<EvidenceClaim>` (non-breaking extension)
- `EvidenceKind::default_claims()` canonical mapping (40+ variants mapped)
- `Evidence::claims()` and `EvidenceList::claims()` / `claims_of_type()`
- 18 new unit tests (including negative tests)

### What was NOT implemented (explicit non-goals)
- ❌ Start/Body/End multi-dimensional confidence algorithm
- ❌ FunctionReality struct
- ❌ x86 Function Discovery changes
- ❌ New evidence sources (ReachableFromEntry, SEH, /GS)
- ❌ Evidence weight changes
- ❌ Confidence formula changes
- ❌ Confirmed threshold changes
- ❌ Decompiler, SSA, Memory SSA, CallGraph changes
- ❌ Ground Truth changes

## 3. Architecture

### Data Model

```rust
pub enum ClaimType {
    FunctionStart,      // This address is a function entry
    FunctionBody,       // Bytes form a valid function body
    FunctionEnd,        // Function ends at this address
    FunctionIdentity,   // This address has a specific identity
    Reachability,       // This address is reachable from somewhere
    ExternalIdentity,   // This is an external identity (import thunk)
    NegativeBoundary,   // This is NOT a function boundary
    ExceptionRegion,    // This is part of exception handling
    Unknown,
}

pub enum ClaimSubject {
    Address(u64),       // Raw address (stable, not string)
    Function(u64),      // Function identified by start address
    Thunk(u64),         // Thunk identified by address
    Unknown,
}

pub enum ClaimStrength {
    Strong,             // Authoritative (PE header, .pdata)
    Supporting,         // Supports but doesn't independently prove
    Contextual,         // Weak context
    Negative,           // Refutes the claim
    Unknown,
}

pub struct EvidenceClaim {
    pub claim_type: ClaimType,
    pub subject: ClaimSubject,
    pub strength: ClaimStrength,
    pub source_evidence: EvidenceKind,  // Traceability
}
```

### Evidence Extension (non-breaking)

```rust
pub struct Evidence {
    pub kind: EvidenceKind,
    pub address: Option<u64>,
    pub detail: Option<String>,
    pub weight: f64,
    #[serde(default)]
    pub claim: Option<EvidenceClaim>,  // NEW: explicit claim, None = derive from kind
}
```

### Claim Resolution Priority

```
Evidence.claim (explicit)  →  use it
Evidence.claim = None      →  EvidenceKind::default_claims(address)
```

## 4. Evidence → Claim Mapping

Canonical mapping in `EvidenceKind::default_claims()`. Key decisions:

| EvidenceKind | ClaimType | Strength | Rationale |
|-------------|-----------|----------|-----------|
| EntryPoint | FunctionStart | Strong | PE header authoritative |
| ExportEntry | FunctionStart | Strong | PE export authoritative |
| PdataEntry | FunctionStart + FunctionEnd | Strong | x64 metadata, both boundaries |
| CallReference | FunctionStart | Supporting | CALL target, not definitive |
| ValidFunctionBody | FunctionBody | Supporting | Body validity, NOT start |
| ReachableFromEntry | Reachability | Supporting | NOT FunctionStart (P0-5.3A) |
| AddressTaken | (none) | — | May be BB label (P0-5.3A) |
| ImportThunk/ExternalCall | ExternalIdentity | Strong | IAT-proven |
| Negative* | NegativeBoundary | Negative | Refutes function boundary |
| CFG edges/targets | (none) | — | CFG-level, not function boundary |

Full mapping: see `docs/P0-5.5_EVIDENCE_CLAIM_MAPPING.md`

## 6. Determinism

- `EvidenceList::claims()` uses `HashSet` for dedup (claim_type + subject), then preserves insertion order via Vec
- Evidence order in EvidenceList is insertion order (Vec)
- FunctionDiscovery uses BTreeMap (sorted by address)
- Same binary → same analysis → same claims → same JSON output

## 9. Known Limitations

1. **Claim Layer is infrastructure only** — no consumer uses claims yet (FunctionReality is P0-5.6)
2. **AddressTaken has no default claim** — requires context-specific assignment (future)
3. **CFG evidence has no function-boundary claim** — correct, but means CFG-only discovered addresses have no claims
4. **Multi-evidence same claim dedup** — keeps first occurrence, doesn't aggregate strength
5. **No Claim aggregation algorithm** — ClaimStrength is per-evidence, not yet combined across evidence

## 13. Highest Principle

This stage did not rename Evidence to Claim. It established the semantic boundary:

> **Evidence supports a specific Claim. A Claim has a Type, a Subject, and a Strength. What an evidence proves must be recorded alongside what it does not prove.**

FOX can now distinguish:
- "ValidFunctionBody supports FunctionBody" from "this is a function start"
- "ReachableFromEntry supports Reachability" from "this is a function"
- "AddressTaken proves nothing by itself" from "this must be a function"

Truth > Confidence. Evidence > Guess. Reality > Metric. Architecture > Patch.
