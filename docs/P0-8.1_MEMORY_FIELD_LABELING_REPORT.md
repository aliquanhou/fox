## 2. 实现方法

### 2.1 两种内存访问形式

FOX 当前有两种内存操作数输出：

1. **Expression::Load { address }** — Expression Recovery 成功恢复了地址
   - 旧输出: `*(esi + 0x190B8)`
   - 新输出: `esi->field_0x190B8`

2. **Expression::Unknown { reason: "memory operand: [esi+0x190b8]" }** — Expression Recovery 无法恢复复杂地址
   - 旧输出: `<?memory operand: [esi+0x190b8]>`
   - 新输出: `esi->field_0x190B8`

### 2.2 try_field_access()

识别 Expression 层的 base+offset 模式：

```
Binary(Add, Variable("esi"), Constant(0x190B8)) → esi->field_0x190B8
Binary(Sub, Variable("esp"), Constant(0x4))     → esp->field_-0x4
Variable("eax")                                  → eax->field_0
```

### 2.3 try_parse_memory_operand()

解析 Unknown reason 字符串中的 `[reg+offset]` 格式：

```
"memory operand: [esi+0x190b8]" → esi->field_0x190B8
"memory operand: [eax]"         → eax->field_0
```

### 2.4 Fail-closed

- 无法解析为 base+offset 的复杂地址 → 保持 `*(...)` 或 `<?...>`
- 不猜测字段类型、字段名含义或结构体边界

## 6. 已知 GAP

### GAP-P0-8.1-GLOBAL-OBJECT（P1）
当前 `[ebx+0x46E920]` 显示为 `ebx->field_0x46E920`，但 +0x46E920 实际上是全局对象基址。
- 预期: `g_global_46E920->field_0x10`（需要先识别 `mov ebx, [0x46E920]` 为全局对象加载）
- 影响: 1,946 个访问
- 下一步: P0-8.2 Global Object Recovery

### GAP-P0-8.1-STACK-VARS（P1）
`[esp+0x2c]` 显示为 `esp->field_0x2C`，但应该是 `local_2c`（局部变量）。
- 需要函数 prologue 分析来区分栈变量和结构体字段
- 影响: 大量栈访问

### GAP-P0-8.1-COMPLEX-ADDR（P2）
2,283 个 `memory operand` 残留 + 1,016 个 `*(` 解引用，是多级间接寻址或复杂地址计算，无法简单解析为 base+offset。
