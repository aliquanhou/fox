## 5. 关键发现 — 真实商业软件与 Golden Sample 的差异

### 5.1 Import Thunk FP (P1)

**现象**: x86 import thunk (`jmp [IAT_entry]`) 被误识别为 High confidence 函数。
**证据**: 0x455E40, 0x455E46 等地址，反汇编确认是 `jmp [0x00456154]` / `jmp [0x0045611C]`。
**影响**: 
- Function Discovery FP 增加（thunk 被当作函数）
- DirectExternal=0（call to thunk 被当作 DirectInternal）
- Call graph 正确性受损
**根因**: FOX 没有 import thunk 识别模式，也没有把 `jmp [IAT]` 目标地址与 IAT/imports 关联。

### 5.2 DirectExternal=0 (P1)

**现象**: 174 个 imports 被正确解析（`fox imports`），但 call graph 中 DirectExternal=0。
**根因**: call graph 构建时，call target 地址与 import thunk/IAT 没有映射。代码 call 一个 import thunk 地址时，FOX 把它当作 DirectInternal call 到 thunk 函数，而不是 DirectExternal call 到 DLL 函数。

### 5.3 x86 无 .pdata (P1)

**现象**: Confirmed 仅 1 个（entry point），其余 156 个 High + 199 个 Probable。
**根因**: P0-3.2 接入的 .pdata/RUNTIME_FUNCTION 是 x64 特有。x86 PE 没有 .pdata section，FOX 缺少 strong evidence 来确认函数边界。
**影响**: Function Discovery confidence 整体偏低，大量函数停留在 High/Probable。

### 5.4 Indirect Call Resolution=0 (P2)

**现象**: IndirectResolved=0, IndirectUnknown=1,461。
**根因**: P0-4.4 实现的 LEA→Store→Load→call chain 可能主要针对 x64（RIP-relative LEA）。x86 使用不同的函数指针加载模式（如 `mov eax, [addr]` / `push addr` / `call eax`）。
**影响**: 1,461 个间接调用无法解析目标。

### 5.5 地址极近的函数 (P2)

0x455E40, 0x455E46, 0x455E4C 三个函数地址差 6/2 字节。
- 0x455E40: import thunk (`jmp [IAT]`)
- 0x455E46: import thunk (`jmp [IAT]`)
- 0x455E4C: 真实函数 entry point
前两个是 FP（import thunk），第三个是真实函数。

### 5.6 可疑数据误反汇编 (P3)

0x455E3C: `add al, 0x50; ret` — 看起来不像真实函数，可能是数据被误反汇编。0x455E3F 是 int3 padding。需要进一步确认是否被 FOX 识别为函数。
