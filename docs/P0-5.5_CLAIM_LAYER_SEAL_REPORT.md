## 2. What P0-5.5 Established

FOX now has a first-version **Evidence → Claim → Subject → Strength** semantic infrastructure:

```
Evidence
  ↓
Claim
  ├── ClaimType (FunctionStart / Body / End / Identity / Reachability / ExternalIdentity / NegativeBoundary / ExceptionRegion / Unknown)
  ├── ClaimSubject (Address(u64) / Function(u64) / Thunk(u64) / Unknown)
  ├── ClaimStrength (Strong / Supporting / Contextual / Negative / Unknown)
  └── source_evidence (EvidenceKind — traceability)
```

Before P0-5.5: `Evidence → confidence → "this is a function"`
After P0-5.5: `Evidence → Claim(specific type, specific subject, specific strength) → Reality`

**Core principle established**: Evidence is not Truth. Evidence supports a specific Claim. What an evidence proves must be recorded alongside what it does not prove.

## 7. P2 GAP (Recorded, NOT Fixed in P0-5.5)

### PdataEntry → FunctionEnd ClaimSubject precision

**Issue**: `PdataEntry` Evidence stores only `address = BeginAddress`. The `.pdata` EndAddress is not carried in the Evidence struct. Therefore:

```
FunctionStart claim → subject = Address(BeginAddress)  ✅ correct
FunctionEnd claim   → subject = Address(BeginAddress)  ❌ imprecise (should be EndAddress)
```

The claim **type** (FunctionEnd) and **strength** (Strong) are correct — `.pdata` does define an end. But the **subject address** points to the function start, not the end.

**Why not fixed in P0-5.5**: Would require modifying the Evidence struct (adding end_address), which risks expanding scope into FunctionReality territory. Per architect decision, this is deferred to P0-5.6.

**Deferred to**: P0-5.6 FunctionReality / Boundary Model

**Full analysis**: `docs/P0-5.5R_CLAIM_LAYER_INDEPENDENT_REVIEW.md` Finding 4
