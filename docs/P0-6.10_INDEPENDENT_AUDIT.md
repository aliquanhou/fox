## 审计项 3：1219 Indirect Unknown vs 1461 口径

**结论：✅ PASS（口径差异已解释）**

### 数字对比
| 口径 | 数量 | 说明 |
|------|------|------|
| CallGraph indirect_unknown | **1461** | 所有 indirect call edge，无 resolved_symbol 且无 callee |
| call_targets map 中 Unknown | **1254** | 去重后（同一 call_instruction 只保留一条） |
| 实际输出 call_unknown | **1219** | 仅在成功反编译的函数中出现的 call |

### 差异解释
1. **1461 → 1254**：CallGraph 中可能存在重复 edge 或同一地址多次记录，HashMap 去重
2. **1254 → 1219**：35 个 Unknown target 在 Failed(18)/Degraded(2) 函数中，或 SSA 未包含该 call 指令
3. 所有 1461 个 indirect_unknown 均在 OK 函数中（函数级），但指令级可能有遗漏

### 结论
1219 个 indirect unknown **确实无法可靠解析**——它们是 `call eax` / `call [memory]` 等间接调用，CallGraph 无法确定 target。保持 `call_unknown` 是正确的 fail-closed 行为。

## 审计项 4：PUSH 参数顺序 — 🔴 P1 BUG

**结论：🔴 FAIL — 参数顺序反转**

### Bug 定位
`structured_ir.rs` 第 648 行：`push_indices.reverse();`

### 逻辑分析

x86 cdecl/stdcall 约定（参数从右往左压栈）：
```
index 0: PUSH arg3    ; 先压，栈深处
index 1: PUSH arg2
index 2: PUSH arg1    ; 后压，栈顶 = 第一个参数
index 3: CALL func
```

C-like 期望：`func(arg1, arg2, arg3)`

### 代码执行追踪
```
从 call_idx=3 往回收集：
  i=2: PUSH arg1 → push_indices = [2]
  i=1: PUSH arg2 → push_indices = [2, 1]
  i=0: PUSH arg3 → push_indices = [2, 1, 0]

push_indices = [2, 1, 0] → [arg1, arg2, arg3] ← 已经是正确顺序！

reverse() 后：[0, 1, 2] → [arg3, arg2, arg1] ← 反转了！
```

### 当前状态
- 整个 1.59MB NtcMach 输出中：**0 个调用有实际恢复的参数**
- 原因：PUSH 指令的 `destination_operand_idx` 为 None（PUSH 隐式写 ESP/内存），`recover_definition()` 返回 `Expression::Unknown`
- Unknown 被 `.filter()` 过滤掉，所以参数列表始终为空
- **Bug 被完全掩盖，当前输出不受影响**

### 风险
一旦未来 ExpressionRecovery 改进为能恢复 PUSH source 值（例如通过 operand 直接读取而非 destination），所有多参数调用将输出反转的参数顺序：
```c
func(arg3, arg2, arg1);  // 错误
```

### 修复方案
删除 `structured_ir.rs` 第 648 行 `push_indices.reverse();`

收集时从离 call 最近的 PUSH 开始（即第一个参数），已经是正确的 C-like 顺序，不需要反转。

### 严重性
- **当前影响：无**（全部被 Unknown 过滤）
- **潜在影响：高**（未来表达式恢复改进后立即暴露）
- **修复成本：极低**（删一行）
- **建议：封板前必须修复**

## 审计项 5：arguments_complete 语义

**结论：🟡 NON-BLOCKING GAP — 部分恢复时省略号有语义歧义**

### 当前逻辑
```rust
let complete = push_indices.len() <= 8;
// ... filter Unknown ...
let complete = complete && args.len() == push_indices.len().min(8);
```

输出规则：
- `args.is_empty() && !complete` → `/* arguments unresolved */` ✅
- `!args.is_empty() && !complete` → `arg1, arg2, ...` ⚠️
- `complete` → `arg1, arg2` ✅

### 问题场景
3 个 PUSH，其中第 2 个无法恢复（Unknown 被过滤）：
- 实际：`func(arg1, <?unknown>, arg3)`
- 输出：`func(arg1, arg3, ...)` ← 省略号暗示"后面还有参数"，但实际缺失的是中间的 arg2

### 建议（非阻塞）
方案 A：过滤 Unknown 时保留占位符 `<?unknown>`，输出 `func(arg1, <?unknown>, arg3)`
方案 B：只要有任何 Unknown 被过滤，就整体输出 `/* arguments unresolved */`

当前行为对于全 Unknown（最常见场景）是正确的。部分恢复场景在当前输出中为 0，因此不阻塞。
