## 2. 实现方法

### 2.1 纯常量地址识别

当内存操作数是纯十六进制常量地址（范围 0x460000-0x480000，即 NtcMach .data 段）：

```
[+0x46E920]  →  global_46E920
[0x46ED78]   →  global_46ED78
```

### 2.2 两种路径

1. **Unknown reason 解析**: `try_parse_memory_operand()` 处理 `memory operand: [+0x46e920]`
2. **Expression::Load**: `try_field_access()` 处理 `Expression::Constant(0x46E920)`

### 2.3 Fail-closed

- 地址不在 .data 段范围（0x460000-0x480000）→ 不命名
- 不猜测语义（不叫 g_machine、g_state）
- 命名固定为 `global_` + 大写十六进制地址

## 6. 已知 GAP

### GAP-P0-8.2-GLOBAL-POINTER-FIELD（P1）
全局对象加载到寄存器后，字段访问仍显示为 `eax->field_XX`，无法追溯到 `global_46E920->field_XX`。
需要简单的寄存器值传播（全局加载 → 后续字段访问合并）。

### GAP-P0-8.2-GLOBAL-SEMANTIC-NAME（P2）
`global_46E920` 是安全命名，但不携带语义。需要初始化函数分析 + 字段聚类才能推断为 `g_machine`。

### GAP-P0-8.2-RESIDUAL-MEMORY（P2）
2,319 个 `memory operand` 残留是复杂寻址（`[eax+ebx*4]`、`[eax+ebx+0x10]` 等），无法简单解析。
