## 2. O2 FN Root Cause 调查结果

### 2.1 关键发现：.pdata 未解析

FOX PE parser 完全未解析 `.pdata` 段。x64 PE 的 `.pdata` 包含 `RUNTIME_FUNCTION` 表（BeginAddress/EndAddress/UnwindData），是 Windows 异常处理使用的**权威函数边界元数据**。

验证：01_linear_O2.exe 的 .pdata 段包含 **1749 个 RUNTIME_FUNCTION** 条目。

### 2.2 O2 FN 根因分类

| FN 类型 | 根因 | 占比 | 解决方案 |
|---------|------|------|---------|
| 有栈帧函数 | 无 pdata 解析 | ~60% | .pdata 解析（P0-3.2 已实现） |
| 极小 leaf 函数 | 无 pdata + 无 CALL 引用 | ~25% | int3 padding + RET 检测（P0-3.2 已实现） |
| 无引用 COMDAT | ICF 折叠后 .map 仍列出但无调用 | ~10% | Ground Truth 定义问题，非 Detection 缺陷 |
| switch/jump-table | 非常规入口 | ~5% | 后续阶段处理 |

### 2.3 典型案例：gt_add (0x140007280)

```asm
lea eax, [rcx+rdx]   ; 2 bytes
add eax, eax          ; 2 bytes
ret                   ; 1 byte
```

- 仅 6 字节，无栈分配，无参数存储
- **不在 .pdata 中**（MSVC 不对无栈操作的极小函数生成异常元数据）
- main 实际调用 0x140002A2C（ICF 折叠后的版本），不调用 0x140007280
- 前有 int3 (0xCC) 填充
- 通过 orphan leaf 检测（int3 padding + RET）成功发现

## 3. Multi-Evidence Function Discovery 架构

### 3.1 证据源（按权重排序）

| 证据源 | 权重 | 类型 | 说明 |
|--------|------|------|------|
| Entry Point | 0.95 | Positive | PE 入口点 |
| Export | 0.90 | Positive | PE 导出表 |
| **.pdata RUNTIME_FUNCTION** | **0.85** | **Positive** | **x64 权威异常元数据（新增）** |
| CALL Reference (≥3) | 0.70 | Positive | 被多次直接调用 |
| CALL Reference (1-2) | 0.50 | Positive | 被直接调用 |
| Function Prologue | 0.40 | Positive | 识别的函数序言 |
| **Orphan Leaf (int3+RET)** | **0.25** | **Positive** | **无 pdata/无引用的 leaf（新增）** |
| Data Section | -0.50 | Negative | 位于数据段 |
| Invalid Instruction | -0.40 | Negative | 无法反汇编 |
| Inside Function | -0.30 | Negative | 位于已确认函数内部 |

### 3.2 发现阶段

```
Phase 1:    Entry Point + Exports (高置信度种子)
Phase 1.5:  .pdata RUNTIME_FUNCTION (x64 权威边界) ← 新增
Phase 2:    全二进制 CALL target 扫描
Phase 3:    CALL targets 加入候选
Phase 4:    Prologue pattern 匹配（低权重补充）
Phase 4.2:  Orphan leaf 检测 (int3 padding + RET) ← 新增
Phase 4.5:  函数体验证 (validate_function_bodies)
Phase 5:    Negative Evidence 过滤
Phase 6:    Confidence 分级
```

### 3.3 禁止"单 Pattern = Function"

任何单一 pattern（prologue / orphan leaf）最多产生 Candidate，最终分类必须经过 Evidence aggregation。Confidence 模型：

```
confidence = max_positive + 0.1*(n-1)*(1-max_positive) - sum(negative)
```

分类阈值：Confirmed ≥0.85, High ≥0.7, Probable ≥0.4, Unknown ≥0.15, Rejected <0.15

## 4. 实现变更

### 4.1 fox-binary
- 新增 `RuntimeFunction` 结构体（begin_rva, end_rva, unwind_rva, begin_va, end_va）
- 新增 `Binary::exception_functions()` 方法，解析 .pdata 段 RUNTIME_FUNCTION 表
- 对无效条目（begin=0, end=0, end≤begin）进行过滤

### 4.2 fox-core
- 新增 `EvidenceKind::PdataEntry`（.pdata 异常元数据证据）

### 4.3 fox-analysis
- 新增 `discover_from_pdata()` 方法（Phase 1.5）
  - 仅 x64 架构
  - 新函数：weight 0.85，设置 end_address
  - 已有函数：追加 weight 0.4 佐证证据，更新 end_address
- 新增 `discover_orphan_leaf_functions()` 方法（Phase 4.2）
  - 扫描 int3 (0xCC) 填充后的非填充地址
  - 反汇编 16 字节，要求含 RET 且不含 CALL
  - weight 0.25（弱证据，依赖后续验证过滤 FP）
