## 4. Deep Dive: 0x46E920

### 4.1 访问模式

| 指标 | 数值 |
|------|------|
| 总访问 | 1,946 |
| 读取 | 1,100 (56.5%) |
| 写入 | 846 (43.5%) |
| 读取函数 | 141 |
| 写入函数 | 130 |

### 4.2 关键特征

- **多写者**: 130 个函数写入，不是单写者初始化模式
- **广泛共享**: 141 个函数读取，是全局共享状态
- **读写集中**: 大量读写发生在 0x4278xx 附近（可能是初始化/主循环）
- **典型模式**: `mov reg, [0x46E920]` → `mov [reg+offset], value`（全局对象指针 → 字段访问）

### 4.3 推断

0x46E920 很可能是一个**全局单例对象指针**：
```c
// 初始化时
g_machine = malloc(sizeof(Machine));
// 使用时
g_machine->status = 1;
g_machine->callback(...);
```

当前 FOX 输出：
```c
eax_1 = <?memory operand: [+0x46e920]>;
eax_1->field_0x20 = 1;
```

理想输出：
```c
eax_1 = global_46E920;
eax_1->field_0x20 = 1;
```

## 7. GAP Registry

### GAP-P0-8.2-GLOBAL-NAMING（P0）
**问题**: 全局地址显示为 `<?memory operand: [+0x46e920]>`，未命名。
**影响**: 1,946+ 次访问（仅 0x46E920）。
**最小修复**: `[+0x46E920]` → `global_46E920`（纯显示层，不猜测语义）。

### GAP-P0-8.2-GLOBAL-POINTER-FIELD（P1）
**问题**: 全局对象加载到寄存器后，字段访问显示为 `eax->field_XX`，无法追溯到全局对象。
**模式**: `mov eax, [0x46E920]` → `mov [eax+0x20], 1`
**理想**: `global_46E920->field_20 = 1`
**需要**: 简单的寄存器值传播（全局加载 → 后续字段访问）。

### GAP-P0-8.2-MULTI-WRITER（P2）
**问题**: 0x46E920 有 130 个写入函数，无法确定单一初始化点。
**影响**: 不能自动推断类型或生命周期。
**策略**: 不猜测，只命名为 `global_46E920`。

### GAP-P0-8.2-INIT-FUNC（P2）
**问题**: 未识别全局对象的初始化函数。
**需要**: 交叉引用写入点 + 函数调用关系。

## 8. 推荐最小下一步：P0-8.2 施工

### 第一阶段：安全命名（纯显示层）

将纯常量地址访问命名为 `global_XXXXXX`：

```
当前: eax = <?memory operand: [+0x46e920]>;
目标: eax = global_46E920;
```

**规则**:
- 只处理 `[+0xXXXXXX]` 纯常量地址
- 命名格式固定为 `global_` + 大写十六进制地址
- **不猜测语义**（不叫 g_machine、g_state 等）
- 不修改 SSA / Memory SSA / Expression Recovery

**预期影响**: 109 个全局地址，约 2,500+ 次访问变得可读。

### 第二阶段：全局指针字段传播（可选）

如果全局对象加载到寄存器后有字段访问：
```
mov eax, [0x46E920]    → eax = global_46E920
mov [eax+0x20], 1      → global_46E920->field_20 = 1
```

这需要简单的寄存器值追踪，可能在 P0-8.2 或 P0-8.3 实现。
