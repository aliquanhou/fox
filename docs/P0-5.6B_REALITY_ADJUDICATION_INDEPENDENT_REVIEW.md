## 1. Reality Adjudication Audit

### 1.1 Claim → Status 路径

```
Evidence
  ↓ default_claims()
EvidenceClaim { claim_type, subject, strength, source_evidence }
  ↓ filter by claim_type + strength != Negative / == Negative
positive: Vec<EvidenceClaim>, negative: Vec<EvidenceClaim>
  ↓ adjudicate_reality()
(RealityStatus, Vec<ClaimContradiction>)
```

### 1.2 裁决规则验证

`adjudicate_reality()` 不是 `max(ClaimStrength)`：

| Positive | Negative | Result | 验证 |
|---|---|---|---|
| None | None | Unknown | ✅ |
| None | Any | Rejected | ✅ |
| Strong | None | Confirmed | ✅ |
| Supporting | None | High | ✅ |
| Contextual | None | Probable | ✅ |
| Strong | Negative | Unknown (conflict) | ✅ |
| Supporting | Negative | Rejected | ✅ |
| Strong+ | Negative weaker | downgrade one tier | ✅ |

**Strength rank**: Unknown=0, Contextual=1, Supporting=2, Strong=3, Negative=4。Negative 作为独立 dominant rank，不与 positive 混排。

### 1.3 冲突记录

每次 positive×negative 组合都生成 `ClaimContradiction { positive_claim, negative_claim, description }`，保留完整可追溯性。

**结论**: ✅ Adjudication 正确，非简单 max 映射。

## 2. Start / Body / End 独立性审计

### 2.1 Claim 过滤验证

`build_function_reality()` 中三个维度独立过滤：

```rust
// Start: 只收 FunctionStart claims
start_positive = claims.filter(|c| c.claim_type == FunctionStart && strength != Negative)
start_negative = claims.filter(|c| c.claim_type == FunctionStart && strength == Negative)

// Body: 只收 FunctionBody claims
body_positive  = claims.filter(|c| c.claim_type == FunctionBody && strength != Negative)
body_negative  = claims.filter(|c| c.claim_type == FunctionBody && strength == Negative)

// End: 只收 FunctionEnd claims
end_positive   = claims.filter(|c| c.claim_type == FunctionEnd && strength != Negative)
end_negative   = claims.filter(|c| c.claim_type == FunctionEnd && strength == Negative)
```

### 2.2 维度偷渡检查

| 检查项 | 结果 |
|---|---|
| FunctionStart Claim 只影响 Start | ✅ |
| FunctionBody Claim 只影响 Body | ✅ |
| FunctionEnd Claim 只影响 End | ✅ |
| InvalidFunctionBody(Negative) 只否定 Body | ✅ (Freeze 11) |
| NonExecutableSection(Negative) 只否定 Start | ✅ |
| Body evidence 不自动提升 Start | ✅ |
| Start evidence 不自动提升 End | ✅ |
| Reachability Claim 不进入任何维度 | ✅ (单独存在，不参与 Start/Body/End) |

**结论**: ✅ 三维度完全独立，无偷渡。

## 4. FunctionRange 审计

### 4.1 构造条件

```rust
let range = if start_status != Rejected && start_status != Unknown
    && end_status != Rejected && end_status != Unknown
{
    end_addr.map(|ea| FunctionRange { start: addr, end_exclusive: ea })
} else {
    None
};
```

### 4.2 range=None 场景验证

| 场景 | range | 验证 |
|---|---|---|
| End Unknown | None | ✅ |
| End Probable 但无精确 address | None | ✅ (end_addr=None) |
| End address == Start address | None | ✅ (filtered by `a != addr`) |
| 只有 estimated_end | None | ✅ (estimated_end 不进入 end_addr) |
| 只有 TailCall(entry-address) | None | ✅ (filtered by `a != addr`) |
| 只有 ValidReturn(entry-address) | None | ✅ (生产中无 ValidReturn) |
| Pdata EndAddress (精确) | Some([start, end)) | ✅ |

### 4.3 [start, end_exclusive) 语义

- FunctionRange 定义注释明确: `Semantics: [start, end_exclusive)`
- start = function entry address
- end_exclusive = 精确 EndAddress (Pdata)
- NtcMach (x86, 无 .pdata): 全部 359 函数 range=None

### 4.4 P3 观察（非阻塞）

FunctionRange 构造时没有显式 `assert!(start < end_exclusive)` 或 `if ea > addr` 守卫。当前 Pdata 元数据保证 EndAddress > BeginAddress，但防御性检查可在未来添加。

**Severity**: P3 (增强项，当前无实际风险)

**结论**: ✅ Range 严格，无伪 Range，无零长度，无逆序。
