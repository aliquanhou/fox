## 1. Implementation Summary

P0-4.4 实现了 FOX 第一个统一的跨域值流层（Cross-domain Value Flow），将已封板的 Register SSA 和 Memory SSA 桥接为统一的数据依赖图。

核心交付物：`crates/fox-analysis/src/value_flow/mod.rs`

四个模块全部实现：
- **4.4.1 Memory DataFlow**: MemoryUse → reaching MemoryDef（基于 Memory SSA use-def chains，跨 CFG）
- **4.4.2 Cross-domain Value Flow**: Register ↔ Memory 双向桥接
- **4.4.3 Basic Alias Classification**: MustAlias / MayAlias / NoAlias / Unknown
- **4.4.4 Function Pointer Propagation**: LEA→Store→Load→call 链路解析

## 2. Architecture Before (P0-4.3)

```
Register SSA                    Memory SSA
  │                               │
  ├── RegisterDef                 ├── MemoryDef
  ├── RegisterUse                 ├── MemoryUse
  ├── Phi                         ├── MemoryPhi
  └── use-def (register-only)     └── use-def (memory-only)

         ❌ 完全断开 ❌

mov [rsp+8], rax    → MemoryDef ✅  但 Register DataFlow 不知道 RAX 存入内存
mov rcx, [rsp+8]    → MemoryUse ✅  但 Register DataFlow 不知道 RCX 来自内存
```

无法建立：`Constant → Register → Memory → Register → Use` 完整值流。

---

## 3. Architecture After (P0-4.4)

```
                    CrossDomainValueFlow
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   Register SSA      Memory SSA      Alias Classification
          │                │                │
          └────────────────┼────────────────┘
                           ▼
                    Value Flow Graph
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
  RegisterToMemory   MemoryToRegister   FunctionPointer
  Edge (Store src)   Edge (Load dest)   Candidates
          │                │                │
          └────────────────┼────────────────┘
                           ▼
                    Unified Def-Use
```

值流链（按架构审计修正后的正确语义）：

```
RAX RegisterDef (MOV RAX, 42)
    ↓ RegisterUse (RAX in Store)
MemoryDef([rsp+8])
    ↓ MemoryUse([rsp+8] in Load)
RCX RegisterDef (value from memory)
    ↓ RegisterUse (RCX in later instruction)
```

## 4. Cross-domain Value Flow (4.4.2)

### 数据结构

```rust
// RegisterUse → MemoryDef: Store 的源寄存器值流入内存
pub struct RegisterToMemoryEdge {
    pub register_use: RegisterUseRef,
    pub register_def: RegisterDefRef,
    pub memory_def: (block, inst, MemoryVariable, version),
}

// MemoryUse → RegisterDef: Load 的内存值流入寄存器
pub struct MemoryToRegisterEdge {
    pub memory_use: (block, inst, MemoryVariable, version),
    pub memory_def: (block, inst, MemoryVariable, version),
    pub register_def: RegisterDefRef,
}
```

### 桥接逻辑

**Bridge 1 — Store 源寄存器**:
- 遍历 Memory SSA 的所有 MemoryDef
- 匹配 (block_id, inst_index) 到 Register SSA 指令
- 找到 source_register 对应的 SSA Variable operand
- 通过 Register SSA use_def_chains 追溯到精确 RegisterDef
- 建立 RegisterUse → MemoryDef 边

**Bridge 2 — Load 目标寄存器**:
- 遍历 Memory SSA 的所有 MemoryUse
- 匹配 (block_id, inst_index) 到 Register SSA 指令
- 找到 destination_register 对应的 SSA Variable operand
- 通过 Memory SSA use_def_chains 追溯到精确 MemoryDef
- 建立 MemoryUse → RegisterDef 边

### 查询方法

```rust
pub fn trace_register_value(&self, block_id, inst_index, register) -> Option<String>
```

返回人类可读的值流链，例如：
```
RCX ← memory[Stack { base: "RSP", displacement: 8 }] ← RAX (def at block 0 inst 0)
```

## 5. Basic Alias Classification (4.4.3)

```rust
pub enum AliasClass {
    MustAlias,    // 确定同一内存位置
    MayAlias,     // 可能相同（保守）
    NoAlias,      // 确定不同
    Unknown,      // 无法判定
}
```

分类规则：

| 组合 | 结果 |
|------|------|
| Stack 同 base+disp | MustAlias |
| Stack 同 base, disp 差 >256 | NoAlias |
| Stack 同 base, disp 差 ≤256 | MayAlias |
| Global 同 address | MustAlias |
| Global 不同 address | NoAlias |
| Heap ↔ Heap | MayAlias |
| Unknown ↔ Unknown | MayAlias |
| Stack ↔ Heap | NoAlias |
| Stack ↔ Global | NoAlias |
| Global ↔ Heap | NoAlias |
| 其他跨类 | MayAlias (保守) |

**Heap/Unknown 保持保守语义**，不借 P0-4.4 偷渡完整 Alias Analysis。

## 6. Function Pointer Propagation (4.4.4)

### 解析路径

**路径 A — LEA Direct**:
```
lea rax, [0x401000]    → RegisterDef(RAX, effective_address=0x401000)
call rax               → RegisterUse(RAX)
                           ↓ use-def chain
                         RegisterDef(RAX) = LEA
                           ↓ effective_address
                         target = 0x401000
```
Confidence: 0.95

**路径 B — LEA → Store → Load → call Chain**:
```
lea rax, [0x402000]    → RegisterDef(RAX)
mov [rsp+10h], rax     → RegisterUse(RAX) → MemoryDef([rsp+10h])
mov rcx, [rsp+10h]     → MemoryUse([rsp+10h]) → RegisterDef(RCX, from-memory)
call rcx               → RegisterUse(R CX)
                           ↓ use-def → RegisterDef(RCX)
                           ↓ memory_to_register → MemoryUse
                           ↓ memory use-def → MemoryDef
                           ↓ register_to_memory → RegisterUse(RAX)
                           ↓ use-def → RegisterDef(RAX) = LEA
                           ↓ effective_address
                         target = 0x402000
```
Confidence: 0.85

**路径 C — Unresolved**:
无法通过上述路径解析时，保持 `ResolutionKind::Unresolved`，target_address = None。
**不猜测、不强行解析。**

### 分类

```rust
pub enum ResolutionKind {
    LeaDirect,           // LEA → call
    LeaStoreLoadChain,   // LEA → Store → Load → call
    Iat,                 // IAT（已由 callgraph 处理）
    Unresolved,          // 无法解析
}
```

## 7. Memory DataFlow (4.4.1)

Memory DataFlow 基于 P0-4.3 已封板的 Memory SSA use-def chains：

- 每个 MemoryUse 通过 `use_def_chains[(block, inst, op_idx)]` 追溯到精确 `(def_block, def_inst, version)`
- 跨 CFG 路径工作（Phi + dominator-tree DFS renaming 已在 P0-4.3 验证）
- if/else 合流点产生 MemoryPhi，Load 追溯到 Phi 版本
- loop 回边产生 MemoryPhi，正确处理循环携带依赖

P0-4.4 不重新实现 Memory DataFlow，而是通过 Cross-domain Value Flow 将其与 Register DataFlow 连接。
