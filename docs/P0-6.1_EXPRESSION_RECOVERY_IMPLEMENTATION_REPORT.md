## 1. Architecture

### 1.1 Position in FOX Pipeline

```
Binary
  ↓ PE Parser
  ↓ Function Discovery
  ↓ CFG
  ↓ IR (L1)
  ↓ Register SSA          ← 输入
  ↓ Memory SSA
  ↓ Value Flow
  ↓ Expression Recovery   ← 本阶段 (NEW, consumer layer)
  ↓ (future) Control Structure Recovery
  ↓ (future) Variable Recovery
  ↓ (future) AST + Emitter
```

Expression Recovery 是 **Consumer Layer**，只读现有 SSA 数据，不修改任何底层分析器。

### 1.2 Module Location

- `crates/fox-decompiler/src/expression.rs` — 核心实现
- `crates/fox-decompiler/src/lib.rs` — 导出
- `crates/fox-decompiler/tests/ntcmach_dogfood.rs` — 真实二进制 Dogfood 测试

### 1.3 Design Principles

1. **结构化数据，不是 String** — Expression 是 enum，可模式匹配、可序列化
2. **Fail-closed** — 无法恢复时返回 `Expression::Unknown`，不猜测
3. **Cycle protection** — SSA 理论上无环，但真实二进制可能产生异常，必须检测
4. **Complexity protection** — max_depth + max_nodes 防止恶意二进制导致 OOM/栈溢出
5. **不污染旧分析** — Function Discovery / CFG / SSA / Memory SSA / Value Flow 全部不变

## 2. Data Model

### 2.1 Expression Enum

```rust
pub enum Expression {
    Constant(u64),
    Variable { name: String, version: u32 },
    Binary { op: BinaryOp, left: Box<Expression>, right: Box<Expression> },
    Unary { op: UnaryOp, operand: Box<Expression> },
    Load { address: Box<Expression> },
    Call { target: CallTarget, arguments: Vec<Expression> },
    Phi { incoming: Vec<PhiIncoming> },
    Unknown { reason: String },
}
```

### 2.2 Supporting Types

| Type | Values |
|---|---|
| `BinaryOp` | Add, Sub, Mul, Div, Mod, And, Or, Xor, Shl, Shr, Sar |
| `UnaryOp` | Neg, Not |
| `CallTarget` | Address(u64), Symbol(String), Unknown |
| `PhiIncoming` | { block_id: usize, value: Box<Expression> } |

### 2.3 ExpressionRecovery

```rust
pub struct ExpressionRecovery {
    pub max_depth: usize,   // default 64
    pub max_nodes: usize,   // default 10000
}
```

Public API:
- `recover_definition(ssa, block_id, inst_idx)` → 恢复某个 SSA 定义的表达式
- `recover_use(ssa, block_id, inst_idx, op_idx)` → 恢复某个操作数使用的表达式
- `recover_return_value(ssa)` → 找到 Return 指令并恢复返回值
- `recover_all_definitions(ssa)` → 恢复函数中所有定义

## 3. Algorithm

### 3.1 Core Flow

```
SSA Value (name, version)
  ↓ def_index lookup
Definition (block, inst)
  ↓ dispatch on SSA op
Mov    → recover(operands[1])
Add/Sub/... → BinaryOp(op, recover(old_dest_version), recover(operands[1]))
Neg/Not → UnaryOp(op, recover(old_dest_version))
Inc/Dec → BinaryOp(Add/Sub, recover(old_dest_version), Constant(1))
Load   → Load(recover_memory_address(operands[1]))
Call   → Call(target, args)
Phi    → Phi(incoming expressions)
Store/Cmp/Test/Jump/... → Unknown(reason)
```

### 3.2 ReadWrite Destination Handling

对于 `add eax, ebx` 这类 ReadWrite 操作：
- SSA 中 `eax` 获得新版本 v2
- 旧值 `eax.v1` 是隐式源操作数
- 通过 `version - 1` 推导旧版本（SSA 中版本按变量单调递增）
- 表达式：`Binary(Add, Variable(eax, v1), Variable(ebx, v1))`

### 3.3 Cycle Detection

递归恢复变量时维护 `visited: Vec<(String, u32)>`：
- 进入 `recover_variable(name, version)` 时 push
- 返回时 pop
- 如果已在 visited 中，返回 `Unknown { reason: "cycle detected" }`

### 3.4 Complexity Protection

- `max_depth`（默认 64）：递归深度超限返回 Unknown
- `max_nodes`（默认 10000）：节点数超限返回 Unknown
- Dogfood 真实二进制使用更保守值（depth=32, nodes=500）

## 5. Memory Integration

- **Load**: 恢复为 `Expression::Load { address }`，address 当前为 `Unknown`（因为 SSA Memory operand 是描述字符串 `[rsp+0x20]`，不是可递归的表达式）
- **Store**: 不产生表达式（返回 Unknown，因为 Store 是语句不是值）
- **Memory address expression recovery**: 留待后续阶段（需要 IR 级别的 Memory operand 结构化信息）

---

## 6. Call Handling

- `Call` 指令恢复为 `Expression::Call { target, arguments }`
- target:
  - `Constant(v)` → `CallTarget::Address(v)`
  - `Label(s)` → `CallTarget::Symbol(s)`
  - `Variable` → `CallTarget::Unknown`（间接调用，留待 P0-6.5）
- arguments: 目标之后的操作数（当前 SSA 中通常为空，因为参数传递在独立指令中）

---

## 7. Phi Handling

- Phi 节点恢复为 `Expression::Phi { incoming: Vec<PhiIncoming> }`
- 每个 incoming 包含 `block_id` 和递归恢复的 `value`
- **不**将 Phi 转换为 if/else（留待 P0-6.2 Control Structure Recovery）

## 8. Cycle & Complexity Protection

### 8.1 Cycle Detection

真实二进制 Dogfood 中实际触发：
```
ecx.1 = (ecx.0 ^ (ecx.0 ^ <?cycle detected at ecx.1>))
```
证明 cycle detection 在真实数据上生效。

### 8.2 Depth Protection

- 默认 max_depth = 64
- 超过深度返回 `Unknown { reason: "max depth exceeded" }`
- 测试验证：10 层深的 Add 链不会栈溢出

### 8.3 Node Protection

- 默认 max_nodes = 10000
- 超过节点数返回 `Unknown { reason: "max nodes exceeded" }`
- Dogfood 使用 500 防止真实二进制函数爆炸

### 8.4 全量 Dogfood 事故记录

首次尝试对全部 359 个函数做 `recover_all_definitions` 导致 `memory allocation failed` / `STATUS_STACK_BUFFER_OVERRUN`。
**根因**：某些函数 SSA 链深 + 全量恢复导致指数级展开。
**修复**：Dogfood 测试限制为 3 个函数、每个 5 个定义、更保守的 max_depth/max_nodes。
**教训**：Expression Recovery 必须有 per-function 资源限制，不能假设所有函数都是良性的。

## 13. Final Verdict

P0-6.1 建立了 FOX 第一个真正的 Decompiler 语义恢复层：

```
机器指令 → FOX IR → Register SSA → Use-Def Chain → Expression Tree
```

核心成果：
1. **结构化 Expression Model**（不是字符串拼接）
2. **SSA use-def 递归恢复**（Mov/Add/Sub/Mul/Div/And/Or/Xor/Shl/Shr/Sar/Neg/Not/Inc/Dec/Load/Call/Phi）
3. **ReadWrite 旧值推导**（version-1）
4. **Cycle detection**（真实二进制上验证生效）
5. **Complexity protection**（max_depth + max_nodes）
6. **Fail-closed**（Store/Cmp/Test/控制流 → Unknown，不猜测）
7. **零污染**（不修改任何已封板的底层分析）

FOX 第一次能够回答："这个 SSA Value 是由什么表达式计算出来的？"

这是从"分析器"到"反编译器"的第一道门。
