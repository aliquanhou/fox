## 1. 架构

### 1.1 定位

Structured IR 是**纯 Consumer 层**，读取已封板的分析结果，聚合成统一的 `DecompilerFunction -> Vec<Statement>` 模型。

```
SSAFunction + FunctionCfg + Vec<ControlStructure>
        ↓
  StructuredIRBuilder::build()
        ↓
  DecompilerFunction { statements: Vec<Statement> }
```

- ❌ CFG
- ❌ SSA / Register SSA
- ❌ Memory SSA
- ❌ Expression Recovery
- ❌ Condition Recovery
- ❌ Control Structure Recovery
- ❌ Function Reality
- ❌ Evidence / Claim

## 2. 数据模型

### 2.1 DecompilerFunction

```rust
pub struct DecompilerFunction {
    pub address: u64,
    pub name: Option<String>,
    pub statements: Vec<Statement>,
    pub evidence: FunctionEvidence,
}
```

### 2.2 Statement (7种)

| Statement | 来源 | 说明 |
|---|---|---|
| `Assign { lhs, rhs, evidence }` | SSA definition + Expression Recovery | `v1 = expr;` |
| `If { condition, then_body, else_body, merge_block, evidence }` | ControlStructure::IfElse | `if (cond) { ... } else { ... }` |
| `GuardClause { condition, body, return_value, evidence }` | ControlStructure::GuardClause | `if (cond) { ...; return; }` |
| `Return { value, evidence }` | CFG Return edge + Expression Recovery | `return expr;` |
| `CallStmt { target, arguments_unresolved, evidence }` | SSA Call instruction | `call_XXXX(/* arguments unresolved */);` |
| `Unknown { reason, condition, goto_target, evidence }` | ControlStructure::Unknown | `/* FOX: reason */ goto loc_XXXX;` |
| `PhiAssign { lhs, incoming, evidence }` | SSA Phi node | `v1 = phi(...); /* SSA phi */` |

### 2.3 Unknown 是一等公民

`Statement::Unknown` 包含：
- `reason: String` — 为什么无法结构化（如 "double return"、"no bounded merge"）
- `condition: Option<ConditionRecovery>` — 条件（如果可恢复）
- `goto_target: Option<u64>` — fallthrough 目标地址
- `evidence: StatementEvidence` — 证据链

输出格式：`/* FOX: reason */ goto loc_XXXX;`

**绝不**因为 emitter 不知道怎么输出就偷偷变成 if。

### 2.4 Evidence 可追溯

每个 Statement 都有 `StatementEvidence`：
```rust
pub struct StatementEvidence {
    pub instruction_addresses: Vec<u64>,  // 源指令地址
    pub block_ids: Vec<usize>,             // 源 CFG 块 ID
    pub reason: String,                     // 检测理由
}
```

Function 级别的 `FunctionEvidence`：
```rust
pub struct FunctionEvidence {
    pub ssa_instructions: usize,
    pub cfg_blocks: usize,
    pub control_structures: usize,
    pub unknown_statements: usize,
    pub budget_exhausted: bool,
}
```

### 2.5 Placeholder 变量诚实标注

`AssignTarget::Variable` 包含 `origin: VariableOrigin`：
- `SSAPlaceholder` — SSA 变量名（如 `eax.v1`），**不是**恢复的变量
- `Recovered` — 未来 Variable Recovery 后使用（P0-6.6A 不实现）

**绝不**把 `v1` 包装成 `object` 或 `local_1`。

## 3. 构建算法

### 3.1 三阶段构建

**Phase 1: 线性语句构建（按 CFG 块）**
- 遍历每个 CFG 块对应的 SSA 块
- Phi 节点 → `PhiAssign`
- Call 指令 → `CallStmt`（arguments_unresolved = true）
- 有 destination 的指令 → `Assign`（rhs 来自 Expression Recovery）
- CFG Return edge → `Return`（value 来自 `recover_return_value`）

**Phase 2: 控制流结构提升**
- 遍历 `Vec<ControlStructure>`
- `IfElse` → `Statement::If`（then/else 块的语句嵌套进去）
- `GuardClause` → `Statement::GuardClause`（body 块语句嵌套，return 块提取 return value）
- `Unknown` → `Statement::Unknown`（reason + goto_target）
- 已处理的块标记为 processed，避免重复

**Phase 3: 剩余块语句补充**
- 按地址顺序遍历未 processed 的 CFG 块
- 将其语句添加到顶层

### 3.2 资源预算

```rust
pub struct StructuredIRBudget {
    pub max_statements: usize,  // 默认 5000
    pub max_depth: usize,        // 默认 32
    current_statements: usize,   // 共享计数器
    exhausted: bool,
}
```

- 每个 Statement 分配前调用 `budget.allocate()`
- 预算耗尽 → `budget_exhausted = true`，停止构建
- **不 panic，不 OOM**
- 0x401390 (114 blocks, 627 instrs, 64 CS) → 204 statements，预算未耗尽

### 3.3 Call Arguments 不恢复

`CallStmt` 明确标记 `arguments_unresolved: true`。
输出：`call_XXXX(/* arguments unresolved */);`

**绝不**凭寄存器位置猜 `foo(object, buffer, count)`。

## 6. 已知限制（Non-Goals）

P0-6.6A **不做**：
- ❌ Variable Recovery（`[esp+4]` → `arg0`）
- ❌ Type Recovery（全部默认 `void` / `int`）
- ❌ Call Argument Recovery（`call_XXXX(/* unresolved */)`）
- ❌ Function Signature Recovery
- ❌ Post-Dominator
- ❌ Loop / Switch Recovery
- ❌ 完整 C AST / C compiler compatibility
- ❌ Ghidra / rev.ng / RetDec 集成
- ❌ Serialize/Deserialize（ConditionRecovery 未 impl serde，后续可加）
