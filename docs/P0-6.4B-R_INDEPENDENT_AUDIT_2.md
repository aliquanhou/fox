## 2. GuardClause 独立验证（n=894）

### 定义
Immediate Return Path = branch target block **自身**在 CFG 中有 Return edge。
禁止把 `block → continuation → return` 算作 immediate return。

### 验证结果

| 指标 | 数量 | 要求 | 结果 |
|---|---|---|---|
| true side immediate return | 528 | — | ✅ |
| false side immediate return | 366 | — | ✅ |
| body also immediate return | **0** | MUST BE 0 | ✅ |
| dual-return (both sides immediate) | **0** | MUST BE 0 | ✅ |

### 分析
- 528 个 GuardClause：taken (ConditionalTrue) 分支为 immediate return（典型 `jz error_block` 模式）
- 366 个 GuardClause：fallthrough (ConditionalFalse) 分支为 immediate return（典型 `jnz continue` 模式，fallthrough 直接返回）
- **0 个 GuardClause 的 body 也有 immediate return** — 证明没有把普通 if/else 误判为 GuardClause
- **0 个 dual-return GuardClause** — 证明 tiebreaker 已彻底删除，双 return 不会被强行塞入 GuardClause

## 5. IfElse 反例搜索

### Counterexample 1: Loop 污染
- **Loop-contaminated IfElse (branch 有 backward successor):** 274
- 但 `find_bounded_common_merge()` 在 BFS 中排除 backward edges（target_address < branch_address），所以这些 IfElse 的 merge 是通过**前向路径**找到的，不是通过 loop back-edge
- 这 274 个是"位于循环内的 if/else"，其分类基于前向路径 merge，loop back-edge 被正确忽略
- **结论: 无 loop 污染导致的错误分类** ✅

### Counterexample 2: Switch / IndirectJump 污染
- **Switch/IndirectJump-contaminated IfElse:** **0** ✅
- 代码路径证据: `recover_control_structures()` 只处理同时有 `ConditionalTrue` + `ConditionalFalse` 边的块 (line 118-132)。IndirectJump 块的边类型是 `EdgeKind::IndirectJump`，天然被排除。

### Counterexample 3: Shared Continuation
- **Functions with shared continuation (多个 IfElse 共享 merge):** 163
- 这是正常现象——真实代码中多个 if 语句共享同一个 continuation block 很常见
- 每个 IfElse 独立检测自己的 merge，不会被错误合并

### Counterexample 4: 异常/错误路径 common merge
- 错误路径和正常路径共享 merge 是 if/else 的正常模式，不是反例
- 所有 3761 IfElse 都有可验证的 merge depth，没有发现异常

## 12. 最终审计结论

### 裁决: **PASS**

### 理由
1. **P0-1 GuardClause 误报已修复:** body also immediate return = 0，dual-return GuardClause = 0。证据优先的 immediate-return 检测正确工作。
2. **P1-1 IfElse merge 已修复:** 3761 IfElse 全部在 8 步内有可验证 merge，77.9% 是 depth 1-2 的典型结构。
3. **P1-2 tiebreaker 已删除:** 双 return 正确进入 Unknown (224个)，无任何 taken=early-return 的强行标注。
4. **无 loop/switch 污染:** switch contamination = 0，loop 分支通过前向路径正确分类。
5. **0x41F000 正确:** GuardClause @ 0x41F010 + Unknown @ 0x41F020（双 return）。
6. **fail-closed 完整:** 所有证据不足的情况都进入 Unknown。

### 非阻塞问题
1. **修复报告 GuardClause 计数错误 (528 vs 实际 894):** 临时脚本 bug，算法正确。建议更新修复报告中的数字。
2. **TEST GAP:** nested if/else、loop contamination、switch contamination、shared continuation 无专门单元测试。NtcMach 全量扫描已覆盖，建议后续补充。

### 建议
