## 2. Findings

### F-01: PE Data Directory 解析不完整

**位置**: `crates/fox-binary/src/pe/mod.rs:70-81`

当前只读取 3 个 Data Directory：
- Index 0: Export Table
- Index 1: Import Table
- Index 5: Base Relocation

**未读取**:
- Index 14: **CLR/COM Descriptor** (IMAGE_DIRECTORY_ENTRY_COM_DESCRIPTOR)

这是 .NET 检测缺失的直接根因。DevExpress DLL 的 CLR Header RVA=0x2008, Size=72，但 FOX 完全忽略。

### F-02: Binary 结构体无 Execution Model

**位置**: `crates/fox-binary/src/lib.rs:42-54`

```rust
pub struct Binary {
    pub format: BinaryFormat,      // PE32 / PE32Plus / ELF / ...
    pub architecture: Architecture, // X86 / X64 / ARM64
    // ... 无 execution_model
    // ... 无 clr_present
}
```

只有 Container Format 和 Architecture，没有 Execution Model。
PE32 + x86 被默认为 Native x86，无法区分 Native vs ManagedCLR。

### F-03: detect_format() 只检测容器格式

**位置**: `crates/fox-binary/src/lib.rs:58-96`

`Binary::detect_format()` 只判断 PE/ELF/Mach-O 容器，不检查执行模型。
PE32 检测通过 Optional Header magic (0x10B)，但不检查 CLR header。

### F-04: analyze_binary() 无 Reality Gate

**位置**: `crates/fox-analysis/src/lib.rs:1123-1147`

```rust
pub fn analyze_binary(binary: &Binary) -> AnalysisResult {
    let functions = FunctionDiscovery::discover(binary);  // 直接进入 Native Pipeline
    // ... CFG, CallGraph, Identity, Pipeline
}
```

问题：
1. **返回 `AnalysisResult` 而非 `FoxResult<AnalysisResult>`** — 无法返回错误
2. **无任何格式/执行模型检查** — 任何 Binary 都直接进入 Function Discovery
3. .NET DLL 的 11MB .text 被当作原生代码扫描 → 挂死

### F-05: 无 UnsupportedExecutionModel 错误类型

**位置**: `crates/fox-core/src/error.rs`

现有错误：
- `UnsupportedBinaryFormat` (ELF/Mach-O 在 load 时使用)
- `UnsupportedArchitecture`
- 但**没有** `UnsupportedExecutionModel`

需要新增错误变体以区分"格式不支持"和"执行模型不支持"。

### F-06: CLI 无 per-command 格式验证

**位置**: `apps/cli/src/main.rs`

所有命令通过 `load_binary()` 加载 Binary，然后直接执行。
- `cmd_info` 输出 format/architecture，但不输出 execution model
- `cmd_analyze` 调用 `analyze_binary()`，对 .NET DLL 挂死
- `cmd_functions` 同样挂死
- `cmd_disasm` 对任意地址反汇编，不检查该区域是否为 native code

### F-07: ELF/Mach-O 在 load 阶段 Fail-Closed（正确）

**位置**: `crates/fox-binary/src/lib.rs:99-107`

```rust
pub fn load(data: Vec<u8>) -> FoxResult<Self> {
    match format {
        BinaryFormat::PE32 | BinaryFormat::PE32Plus => pe::PE::parse(...),
        _ => Err(FoxError::UnsupportedBinaryFormat(...)),
    }
}
```

ELF/Mach-O 在 `Binary::load()` 阶段就返回错误，不会进入 analyze。这是正确的 Fail-Closed 模式，应该作为 CLR 处理的参考。

### F-08: characteristics 字段读取但未使用

**位置**: `crates/fox-binary/src/pe/mod.rs:47, 144`

`characteristics` 被读取但 `let _ = characteristics;` 丢弃。
可用于辅助判断（如 DLL vs EXE, 32-bit machine 等），但当前不需要。

### F-09: 无 timeout / cancellation 机制

整个分析链是同步阻塞的，无超时保护。
大文件或恶意构造文件可能导致无限循环或长时间挂起。

## 4. Architecture Proposal

### 4.1 新增 ExecutionModel 枚举

```rust
pub enum ExecutionModel {
    Native,        // 原生机器码 (x86/x64/ARM64)
    ManagedCLR,    // .NET CLR (IL)
    MixedMode,     // CLR + Native (C++/CLI)
    Unknown,
}
```

### 4.2 扩展 Binary 结构体

在 `Binary` 中新增：
```rust
pub execution_model: ExecutionModel,
pub clr_present: bool,
pub reality_evidence: Vec<RealityEvidence>,  // 或复用现有 Evidence
```

### 4.3 CLR Detection (在 PE::parse 中)

读取 Data Directory[14]:
```rust
let clr_dd_rva = read_u32(data, dd_offset + 14*8)?;
let clr_dd_size = read_u32(data, dd_offset + 14*8 + 4)?;
let clr_present = clr_dd_rva != 0 && clr_dd_size != 0;
```

辅助证据（非 canonical）：
- import 包含 mscoree.dll 且函数为 _CorDllMain / _CorExeMain

### 4.4 ExecutionModel 分类逻辑

```
if clr_present:
    if has_native_code_sections_beyond_thunk:
        MixedMode
    else:
        ManagedCLR
else:
    Native
```

本阶段 MixedMode 可以保守归为 ManagedCLR（Safe Stop），不做精确区分。

### 4.5 Safe Dispatch

修改 `analyze_binary` 签名：
```rust
pub fn analyze_binary(binary: &Binary) -> FoxResult<AnalysisResult> {
    match binary.execution_model {
        ExecutionModel::Native => { /* existing pipeline */ }
        ExecutionModel::ManagedCLR | ExecutionModel::MixedMode => {
            Err(FoxError::UnsupportedExecutionModel(...))
        }
        ExecutionModel::Unknown => {
            Err(FoxError::UnsupportedExecutionModel(...))
        }
    }
}
```

**注意**: 这是 breaking change。需要更新所有调用方（CLI, tests）。

### 4.6 CLI 行为

- `fox info`: 输出 execution_model + clr_present
- `fox analyze`: 对 ManagedCLR 快速返回错误（非零退出码）
- `fox functions`: 同上
- `fox disasm`: 对 ManagedCLR 拒绝，除非用户明确指定且地址可证明为 native code

### 4.7 Reality Evidence

每个 Reality Detection 结论携带 Evidence：
```
RealityEvidence {
    kind: ClrHeaderDetected,
    source: "PE Data Directory[14]",
    detail: "RVA=0x2008, Size=72",
}
```

## 5. Implementation Boundary

### 必须修改
- `crates/fox-binary/src/pe/mod.rs`: 读取 CLR Data Directory
- `crates/fox-binary/src/lib.rs`: 新增 ExecutionModel, Binary 字段, detect_reality()
- `crates/fox-core/src/error.rs`: 新增 UnsupportedExecutionModel
- `crates/fox-analysis/src/lib.rs`: analyze_binary 返回 FoxResult, 添加 dispatch
- `apps/cli/src/main.rs`: 所有命令处理新错误类型, info 输出 execution_model

### 不得修改
- Function Discovery 算法
- CFG / SSA / DataFlow / Memory SSA / Value Flow 语义
- Evidence 核心结构
- P0-4.4 已封板能力

### 测试
- Unit: CLR detection, ExecutionModel classification, dispatch
- Integration: DevExpress DLL (必须 Safe Stop, Native Pipeline 调用次数=0)
- Regression: 所有现有 Native 样本不得退化

---

## 6. Audit Conclusion

当前 FOX **没有 Binary Reality Gate**。PE parser 不读取 CLR header，Binary 模型不区分执行模型，analyze_binary 对任何 PE 都直接进入 Native Pipeline。这导致 .NET DLL 被当作原生 x86 扫描并挂死。

修复路径清晰且范围可控：在 PE parser 中增加 CLR detection，在 Binary 中增加 ExecutionModel，在 analyze_binary 前增加 Safe Dispatch。这是 P0 级阻断问题，必须在 P0-4.5 中解决。

**Audit 完成，允许进入 Architecture + Implementation。**
