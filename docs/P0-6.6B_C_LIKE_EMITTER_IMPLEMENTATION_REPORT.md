## 2. Emitter 架构

### 2.1 核心类型

```rust
pub struct EmitterConfig {
    pub annotate_evidence: bool,   // 显示 /* @0x401234 */ 证据注解
    pub show_phi: bool,             // 显示 SSA phi（默认 elide）
    pub indent: String,             // 缩进字符串（默认4空格）
    pub show_header: bool,          // 显示函数头注释
}

pub struct CLikeEmitter { config: EmitterConfig }
```

### 2.2 三种输出模式

| 模式 | Evidence | Phi | Header | 用途 |
|---|---|---|---|---|
| `emit_c_like()` (默认) | ✅ | ❌ | ✅ | 带证据注解的标准输出 |
| `emit_c_like_clean()` | ❌ | ❌ | ❌ | 干净输出，无注解 |
| `EmitterConfig::annotated()` | ✅ | ❌ | ✅ | 显式注解模式 |

### 2.3 7种 Statement 输出格式

| Statement | 输出格式 |
|---|---|
| `Assign` | `v1 = expr; /* @0x401234 */` |
| `If` | `if (cond) { ... } else { ... }` |
| `GuardClause` | `if (cond) { ...; return val; }` |
| `Return` | `return expr; /* @0x401234 */` |
| `CallStmt` | `call_0x401000(/* arguments unresolved */);` |
| `Unknown` | `/* UNKNOWN: reason */ goto loc_0x401234;` |
| `PhiAssign` | `v1 = phi(...); /* SSA phi */`（默认 elide） |

## 4. Target B: 0x41F000 实际输出

**函数特征:** 4 blocks, 41 instrs, 2 control structures（1 Guard + 1 Unknown）。

```c
// Function @ 0x41F000 (sub_000000000041F000)
// SSA instrs: 41, CFG blocks: 4, CS: 2, Unknown: 1, Budget: ok
void func_41F000() {
    if ((eax.v0 & eax.v0) == 0) { /* @0x41F010 */
        call_unknown(/* arguments unresolved */); /* @0x41F018 */
        return <?void return>;
    }
    /* UNKNOWN: no bounded merge and no evidence-first guard clause */ goto loc_41F022; /* @0x41F020 */
    esp_1 = (esp.0 - 40); /* @0x41F000 */
    call_unknown(/* arguments unresolved */); /* @0x41F008 */
    ecx_1 = <?memory operand: [esp+0x2c]>; /* @0x41F022 */
    call_unknown(/* arguments unresolved */); /* @0x41F027 */

}
```

**验证:**
- ✅ GuardClause @ 0x41F010（test eax,eax + jz → early return）
- ✅ Unknown @ 0x41F020（double return → 不编造 if，输出 goto）
- ✅ 2 个 CallStmt（arguments unresolved，不编造参数）
- ✅ Return 语句
- ✅ Evidence 注解完整
- ✅ 不编造参数/类型/变量含义

## 6. Unknown 示例

P0-6.6B 严格遵守"宁可输出 UNKNOWN，也不能猜"原则：

```c
/* UNKNOWN: no bounded merge and no evidence-first guard clause */ goto loc_41F022; /* @0x41F020 */
```

- reason: "no bounded merge and no evidence-first guard clause"
- goto_target: 0x41F022（fallthrough 目标）
- Evidence: @0x41F020（分支指令地址）

0x401390 中有 5 个这样的 Unknown，全部保留为 goto，不编造 if/else。

## 9. 已知 GAP

### GAP-P0-6.6B-1: Expression Display 格式不一致

- AssignTarget 使用 `name_version`（如 `ebp_1`）
- Expression 内部变量使用 `name.version`（如 `ebp.0`）
- 原因：Expression Display 是 P0-6.1 封板的，Emitter 不修改它
- 影响：输出中变量名格式不统一，但语义正确
- 修复时机：后续 Variable Recovery 阶段统一

### GAP-P0-6.6B-2: Memory/Unknown Expression 显示为 `<?...>`

- 如 `<?memory operand: [esp+0x2c]>`、`<?void return>`、`<?cycle detected at esi.4>`
- 原因：Expression Recovery 对无法恢复的表达式输出 Unknown，Display 用 `<?...>` 格式
- 影响：输出不够美观，但诚实表达了"FOX 不知道这个值"
- 修复时机：后续 Expression Recovery 增强

### GAP-P0-6.6B-3: Call target 部分为 `call_unknown`

- 0x41F000 中 2 个 call 显示为 `call_unknown`
- 原因：SSA Call 指令的 target operand 无法解析为地址或符号
- 影响：无法看到调用目标，但不编造
- 修复时机：后续 Call Reconstruction 阶段

### GAP-P0-6.6B-4: 嵌套结构缺失（继承自 P0-6.6A）

- 所有 if/guard 在顶层，无递归嵌套
- 已登记为 `GAP-P0-6.6A-NESTED-STRUCTURE`，非阻塞
- 影响：复杂函数的控制流结构是扁平的，但语义正确
- 修复时机：后续阶段

### GAP-P0-6.6B-5: Phi 表达式极长

- 0x401390 中某些 Phi 嵌套极深，单行可达数千字符
- 原因：Phi 节点在 merge 块处聚合多个 incoming，且嵌套 phi 未展开
- 影响：输出可读性差，但默认 elide Phi（show_phi=false）
- 修复时机：后续 Phi elimination 阶段
