## 1. 审计裁决与返工范围

P0-3.4 独立审计发现 **Precision 指标口径错误**：
- 报告称 Precision=41.94%，同时称"分母=FOX 发现的所有函数（~4260），分子=GT 匹配函数（~26）"

## 2. R1-R2: Precision 修正与指标体系

### 2.1 真实 Precision 计算逻辑

审计 `ground_truth_validation.rs` 后确认：

```
FP 只统计：FOX 发现的函数地址 ∈ [gt_min, gt_max] 且不在 Ground Truth 中
```

其中 `[gt_min, gt_max]` 是 GT 函数的地址范围（如 09_function_pointer_O2: 0x1400072A0 ~ 0x140007340）。

CRT/runtime 函数（~4200 个）在 GT 范围之外，**不计入 FP**。

### 2.2 修正后的指标

| 指标 | 值 | 定义 |
|------|-----|------|
| **GT-region Precision** | **41.94%** | TP / (TP + FP)，FP 仅统计 GT 地址范围内 |
| **GT-region Recall** | **100.00%** | TP / (TP + FN) |
| **GT-region F1** | **59.10%** | 2PR / (P+R) |
| **Binary-wide Precision** | **N/A** | 需要完整 Binary-wide Ground Truth |
| **Binary-wide Recall** | **N/A** | 同上 |
| TP | 52 | GT 函数被 FOX 正确发现 |
| FP | 72 | GT 范围内 FOX 发现但不在 GT 中 |
| FN | 0 | GT 函数未被发现 |
| TN | 估算 | (GT region bytes / 32) - (TP + FP) |

### 2.3 机器可读 JSON 输出

新增输出：`tests/ground_truth/results/ground_truth_metrics.json`

包含：
- 聚合指标（precision/recall/f1/TP/FP/FN）
- 每个样本的详细指标（SampleMetrics）
- MetricDefinitions（明确定义每个指标的计算方式）
- Binary-wide Precision = "N/A"（禁止估算）

### 2.4 指标定义（写入 JSON）

```
GT-region Precision: TP / (TP + FP), where FP only counts FOX-discovered
  addresses within the GT function region [gt_min, gt_max] that are not
  in Ground Truth. Excludes CRT/runtime outside GT region.

GT-region Recall: TP / (TP + FN), where FN = GT functions not found by FOX.

Binary-wide Precision: N/A without complete binary-wide Ground Truth covering
  all functions (application + CRT + runtime + compiler-generated).
```

## 3. R3: Thunk False Positive Regression

### 3.1 测试内容

验证函数体内的 JMP（如 `jmp L1` in if/else）**不会**被错误识别为 ThunkRedirect。

### 3.2 测试用例

1. **`thunk_fp_regression_function_body_jmp_not_thunk`**
   - 对 02_if_else_O2，验证所有 Thunk identity 的 thunk_target 指向可执行 section
   - 验证 Thunk 数量合理（仅 MSVC jump islands，非函数体 JMP）

2. **`thunk_fp_regression_redirect_relations_valid`**
   - 对 08_switch_O2，验证每个 ThunkRedirect relation：
     - from 地址必须是 Thunk identity
     - to 地址必须是 Canonical/Folded/Thunk（允许链式 thunk）

### 3.3 结果

- 02_if_else_O2: 所有 Thunk identity 有有效 target
- 08_switch_O2: 所有 ThunkRedirect relation 有效
- **6/6 通过**

## 4. R4: Address-Taken Negative Tests

### 4.1 测试内容

验证 AddressTaken evidence（weight 0.4-0.55）**单独**不会产生 Confirmed function（需 confidence >= 0.85）。

### 4.2 测试用例

1. **`address_taken_negative_evidence_alone_not_confirmed`**
   - 对 09_function_pointer_O2，统计只有 AddressTaken evidence（无其他强证据）的函数
   - 断言所有此类函数 confidence < 0.85
   - 统计 AddressTaken + Confirmed 的函数，断言都有其他强证据（pdata/CALL/thunk）

2. **`address_taken_negative_not_all_executable_addresses_are_functions`**
   - 对 08_switch_O2，验证落在其他函数地址范围内的 AddressTaken 函数（可能是 basic block / jump table target）confidence < 0.85

### 4.3 结果

- 09_function_pointer_O2: AddressTaken-only = 71 个（全部 < Confirmed），AddressTaken+Confirmed = 17 个（全部有其他强证据）
- 08_switch_O2: 90 个 AddressTaken 函数，无任何落在其他函数内的是 Confirmed
- **6/6 通过**

## 9. 已知限制

1. **Binary-wide Precision = N/A**：需要包含所有应用函数（不仅 gt_*）的完整 Ground Truth 才能测量。当前框架已支持，待后续补充。
2. **ICF 完整建模**：当前 SourceFunctionIdentity 基于命名函数（非 sub_*）。完整的 ICF 检测需要 PDB 或 linker map 中的 source symbol 信息。Framework 已建立，correctness 待 PDB/map 驱动验证。
3. **TN 是估算值**：(GT region bytes / 32) - (TP + FP)。精确 TN 需要 instruction-level 分析。
4. **Identity Error 统计**：当前为 0（框架已预留字段），完整的 identity error 检测需要 PDB/map 对比。
