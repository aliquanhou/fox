## 2. 修改内容

### 2.1 修正类型误判

**P0-9.2（有问题）**:
```
>=20 accesses → BooleanLike
```

**P0-9.3（修正）**:
```
>=20 accesses → IntegerLike (high-frequency state)
```

**原因**: 高频访问字段更可能是计数器/状态变量，而非布尔值。布尔值通常访问次数适中，不会达到 20+。

### 2.2 置信度规则

| 条件 | 候选类型 | 置信度 |
|------|----------|--------|
| in cluster AND >=5 | struct-field | MEDIUM |
| >=20 accesses | IntegerLike | MEDIUM |
| >=10 accesses | DWORD/state | LOW-MEDIUM |
| >=3 accesses | DWORD | LOW |
| 1-2 accesses | UNKNOWN | insufficient |

## 4. 已知限制（GAP）

### GAP-P0-9.3-OPERATION-PATTERN（P1）
当前仍基于访问频率推断。真正的 SSA 行为分析需要：
- 字段被 cmp/test 后接 jcc → BooleanLike
- 字段被 call 使用 → FunctionPointerLike
- 字段被解引用 → PointerLike

这些需要 Statement 级别的操作模式分析，当前 emitter 层无法实现。
