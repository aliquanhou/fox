## 0. 核心问题

> FOX 目前能不能把一个真实 NtcMach 函数还原成人能读懂的伪 C？
> 如果不能，下一块最值得施工的是什么？

**简短回答:** 不能。FOX 已经拥有反编译所需的全部分析层（SSA、Expression、Condition、Control Structure），但缺少将这些分析结果组装成可读代码的**呈现层**（AST + C-like Emitter + Variable Recovery）。最值得先做的是 **AST + 最小 C-like Emitter**，因为它能立即让已有分析结果第一次变成人类可读的输出。

## 4. 核心问题回答

### Q: FOX 目前能不能把一个真实 NtcMach 函数还原成人能读懂的伪 C？

**A: 不能。**

虽然 FOX 已经能够：
- 恢复表达式树（`(x + y) * 4`）
- 恢复条件（`eax == 0`）
- 恢复控制结构（IfElse / GuardClause）
- 追踪完整 Evidence 链

但是这些结果目前只能以**内部数据结构**存在，没有任何方式将它们组装成人类可读的代码。缺少：
1. **AST 层**：没有把 Expression + Condition + ControlStructure 组装成 Function AST 的机制
2. **C-like Emitter**：没有把 AST 输出成文本的机制
3. **Variable Recovery**：没有把 SSA value / stack offset 映射成有意义的变量名
4. **Call Arguments**：没有把调用约定下的寄存器/栈参数还原成函数参数

### 一个具体例子

对于 0x41C9A8（极简函数，1 block，6 instrs，100% expr recovery），FOX 内部已经知道：
```
v1 = load([esp+4])
v2 = v1 + 5
return v2
```

但是无法输出：
```c
int func_41C9A8(int arg0) {
    return arg0 + 5;
}
```

因为缺少 Variable Recovery（`[esp+4]` → `arg0`）和 AST/Emitter（把内部结构变成文本）。

## 5. 下一步建议

### 5.1 最值得先做的：AST + 最小 C-like Emitter

**理由:**
1. **立即产出可见结果**：AST + Emitter 能让已有分析结果第一次变成人类可读的输出
2. **不依赖 Variable Recovery**：可以先用通用变量名（`v1`, `v2`, `stack_20`），后续再替换成有意义的名字
3. **验证分析层的正确性**：可读输出是检验 Expression/Condition/ControlStructure 是否正确的最佳方式
4. **为 Variable Recovery 提供目标**：有了 Emitter，才知道 Variable Recovery 需要输出什么格式

**最小闭环:**
```
Function
  ↓ Statements (from CFG blocks + SSA instructions)
    ↓ Assignment (from Expression Recovery)
    ↓ If/Else (from Control Structure)
    ↓ GuardClause / Early Return
    ↓ Return (from Return edge + Expression)
  ↓ C-like Emitter
    ↓ int func_XXXX(...) {
    ↓     v1 = ...;
    ↓     if (...) { ... }
    ↓     return ...;
    ↓ }
```

### 5.2 第二优先：Variable Recovery

在 AST/Emitter 之后，做基础的 Variable Recovery：
- `[esp+N]` → `argN`（函数参数）
- `[ebp-N]` / `[esp-N]` → `local_N`（局部变量）
- SSA value → `vN`（临时变量）
- 不需要 Type Recovery，先用 `int` / `void*`

### 5.3 第三优先：Call Arguments + Return Value

- 恢复 cdecl/stdcall 调用约定下的参数
- 恢复返回值（eax / edx:eax）

### 5.4 不建议现在做

- ❌ Type Recovery（需要 Variable Recovery 先完成）
- ❌ Loop / Switch Recovery（P0-6.4B-R 已经覆盖 if/else/guard，loop/switch 是更大的工程）
- ❌ 集成 Ghidra/rev.ng/RetDec（FOX 的分析层还没验证完毕，先把自有输出跑通再考虑集成）

P0-6.5 审计确认：
- FOX 的**事实/证据层**已经足够扎实（SSA、Expression、Condition、ControlStructure、Evidence、Claim、FunctionReality）
- 缺少的是**呈现层**（AST + Emitter + Variable Recovery）
- 先建立最小呈现层，让 FOX 第一次能输出可读代码，再决定是否需要集成外部引擎

**最终验收标准不变：把 NtcMach 商业制版软件真正搞明白。**
