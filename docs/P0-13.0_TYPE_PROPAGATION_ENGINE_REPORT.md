## 2. 真实数据结构

```rust
pub enum TypeKind {
    Unknown,
    Integer { bits: u32 },
    Pointer { target: Option<u64> },
    Struct  { object: String },
    Boolean,
    FunctionPointer,
}
pub struct TypeCandidate { kind, confidence: TypeConfidence, evidence: Vec<String> }
pub enum TypeKey { Param(callee,index), Return(callee), Field(object,offset) }
pub struct TypeMap { candidates: HashMap<TypeKey, TypeCandidate> }
```

**命名纪律**：只输出 `integer-candidate(32b)` / `pointer-candidate` / `boolean-candidate`，
**绝不**输出 `int` / `char*` / `bool` / struct 名。

### Pipeline
```
SignatureMap (P0-12)
  ├─ 参数 source: Constant/Computed → Integer{32}  LOW/MEDIUM
  │               MemoryLoad         → Pointer{None} LOW
  │               Register/Unknown   → Unknown (fail-closed)
  ├─ ReturnEvidence::Condition → Boolean LOW
  │               Value/Unknown → Unknown
  └─ FieldTypeFact{deref,arith} → Pointer / Integer (接口预留)
  ▼
TypeMap
```

### TypeJoin（Phase 6）
- 两个证据 kind **相同** → 合并、confidence 取大
- **冲突**（如 Integer vs Pointer）→ **Unknown + evidence "conflict: ..."**，禁止强行选择

### Query（Phase 7）
`get_type(TypeKey)` / `param_type(callee,index)` / `return_type(callee)` / `field_type(object,offset)` / `known_count()`

## 6. 禁止事项遵守

- 无证据 / Register 来源 → Unknown，不猜
- 类型名只到 `integer-candidate`，**未生成 int/char*/bool**
- emitter 只 `set_type_map()` 读取，不 `if offset==8: int`
- 冲突证据 join → Unknown，不强行选择
- 未根据变量名/API名/函数名猜类型

## 7. 已知 GAP

1. **字段类型未接 NtcMach**：`FieldTypeFact` 接口已建，但 P0-8 field access 统计在 emitter 内部（per-function clear），本阶段 batch 传空——字段类型统计为 0。需后续把 P0-8 field evidence 提升到 analysis 层。
2. **bits 固定 32**：未区分 8/16/32/64 位。
3. **Pointer target 未解析**：只到 `pointer-candidate`，未关联 global object。
4. unknown≈47.7% 略低于 >50% 软目标——因 P0-11.3 常量参数占比高（const=1585），属真实证据，未降标准凑 Unknown。
5. FunctionPointer 规则未启用（需 indirect-call 字段）。
