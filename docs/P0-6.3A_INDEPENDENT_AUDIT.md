### Audit 1: FLAGS SSA 单模型 — PASS

**检查:** 全仓库搜索 `eflags|rflags`（rust代码）

**结果:**

**SSA 构造路径:** 仅 2 条（`construct` 简化 + `construct_proper`/`rename_block_dfs` 正式），均处理 FLAGS。

### Audit 2: FLAGS Write/Read/version/phi — PASS

**简化路径** (`ssa/mod.rs:216-237`):
- Write/ReadWrite → `variable_versions["FLAGS"] += 1`
- Read → `variable_versions.get("FLAGS").unwrap_or(0)`

**正式路径** (`ssa/mod.rs:565-611`):
- Write/ReadWrite → `push_version("FLAGS")` + 记录 `version_def` + `def_use`
- Read → 当前版本 + 记录 `use_def_chains`
- Phi placement: `all_writes()` 含 "FLAGS"（writes_flags=true时）→ 进入 def_blocks → phi_placement → FLAGS phi 节点

**一致性:** 两条路径语义一致（Write→新版本，Read→当前版本）。生产代码（pipeline.rs:224, value_flow 5处）全部使用 `construct_proper`。

### Audit 4: FLAGS use-def Producer→Consumer — PASS

**机制:**
1. CondJump 指令中 FLAGS Read → 查找 `use_def_chains[(block_id, inst_idx, flags_op_idx)]`
2. use_def_chains 在正式 SSA 构造中为 FLAGS Read 记录（`ssa/mod.rs:592-609`）
3. 若 `version_def` 中有对应版本 → 记录真实 (def_block, def_inst)
4. 若为初始版本 v0 → 记录 `(usize::MAX, usize::MAX, 0)` 表示外部输入

**验证:** NtcMach 0x401390 dogfood 中 64/64 CondJump 全部 resolved，0 ProducerNotFound，证明 use_def 链对所有条件跳转有效。

**NON-BLOCKING GAP-B:** `IROp::CondJump { condition }` 的 condition 字段未传播到 `SSAInstruction`（SSAInstruction.op 是 String "CondJump"）。condition recovery 通过 `original_mnemonic` 获取条件，可靠但非直接消费 IR condition。未来可在 SSAInstruction 加 `condition: Option<JumpCondition>` 字段。

### Audit 5: ConditionRecovery Evidence 链 — PASS

**恢复流程（`condition.rs:134-238`）:**
1. `inst.op == "CondJump"` — 基于 SSA op 字符串（来自 IROp::name()）
2. `mnemonic_to_condition(original_mnemonic)` — 真实指令助记符
3. 定位 FLAGS operand 索引
4. `use_def_chains` 追踪 producer — 真实 SSA use-def
5. producer.op == "Cmp" 或 "Test" — 基于 SSA op
6. 提取非 FLAGS 操作数作为 left/right — 真实 SSA 操作数
7. 返回 `Condition { operator, left, right, flags_producer_address, branch_address, is_test }`

**Fail-closed:**
- use_def 缺失 → `ProducerNotFound`
- producer 非 CMP/TEST → `ProducerNotCmpTest`
- 无 FLAGS operand → `ProducerNotFound`
- **无任何启发式猜测或 opcode pattern matching**
