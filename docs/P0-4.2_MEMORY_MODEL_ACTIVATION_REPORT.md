## 2. Reality Audit（施工前）

P0-4.1 封板后，核对 `7142e25` 实际代码，确认以下问题：

### 2.1 MemoryOperation 使用布尔标记

```rust
// P0-4.1 (before)
pub struct MemoryOperation {
    pub address: u64,
    pub is_load: bool,      // ❌ 布尔标记，非语义对象
    pub is_store: bool,     // ❌ is_load=true && is_store=true 可能但不明确
    pub location: MemoryLocation,
    pub data_register: Option<String>,  // ❌ 含义模糊
}
```

### 2.2 data_register 使用"第一个非内存 operand"启发式

```rust
// P0-4.1 pipeline.rs mount_memory_analysis()
let data_register = inst.operands.iter().find_map(|o| {
    if let IROperand::Register { name, .. } = o {
        Some(name.clone())  // ❌ 不区分 destination/source
    } else { None }
});
```

对于 `mov [rsp+8], rax`，第一个 register operand 可能是 RSP（在 memory operand 内部），但代码只看顶层 Register operand，所以会找到 RAX。然而这仍然是启发式，不基于 access mode。

### 2.3 mount_memory_analysis() 放在 pipeline.rs

内存语义分析逻辑（65行）放在 fox-analysis/pipeline.rs，而非 fox-ir/memory.rs。这违反模块边界——内存语义是 IR 层的能力，不应由 analysis pipeline 实现。

### 2.4 MemoryOperation 无 Evidence

P0-4.1 的 MemoryOperation 只有 `address`（指令地址），没有 `evidence_detail`。无法追溯"为什么这是 Load/Store"。

### 2.5 L1 translator 正确设置 OperandAccess

审计确认：`fox-ir/src/l1.rs` 的 `translate_operands()` 基于结构化 `op.is_read`/`op.is_write` 设置 `OperandAccess`，**非字符串解析**。

```rust
let access = match (op.is_read, op.is_write) {
    (true, true) => OperandAccess::ReadWrite,
    (true, false) => OperandAccess::Read,
    (false, true) => OperandAccess::Write,
    _ => OperandAccess::Read,
};
```

这意味着 Memory operand 的 `access` 字段已经可靠地区分 Load（Read）和 Store（Write）。P0-4.2 只需正确消费这个结构化信息。

## 3. MemoryOperationKind 语义枚举

### 3.1 设计

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum MemoryOperationKind {
    Load,       // 从内存读取 (mov rcx, [mem])
    Store,      // 写入内存 (mov [mem], rax)
    ReadWrite,  // 同时读写 (lock add [mem], imm, xchg [mem], reg)
    Unknown,    // 无法从结构化 IR 判定
}
```

### 3.2 从 OperandAccess 映射

```rust
impl MemoryOperationKind {
    pub fn from_access(access: OperandAccess) -> Self {
        match access {
            OperandAccess::Read => MemoryOperationKind::Load,
            OperandAccess::Write => MemoryOperationKind::Store,
            OperandAccess::ReadWrite => MemoryOperationKind::ReadWrite,
        }
    }
}
```

**关键：** 映射基于结构化 `OperandAccess`，**不涉及任何字符串解析或汇编文本匹配**。

### 3.3 向后兼容辅助方法

```rust
impl MemoryOperationKind {
    pub fn is_load(&self) -> bool {
        matches!(self, MemoryOperationKind::Load | MemoryOperationKind::ReadWrite)
    }
    pub fn is_store(&self) -> bool {
        matches!(self, MemoryOperationKind::Store | MemoryOperationKind::ReadWrite)
    }
}
```

`MemoryAnalysis::load_count()`/`store_count()` 继续工作。

## 4. MemoryOperation 语义对象

### 4.1 新结构

```rust
pub struct MemoryOperation {
    pub instruction_address: u64,     // 产生此操作的机器指令地址
    pub kind: MemoryOperationKind,     // 语义操作类型（替代 is_load/is_store）
    pub location: MemoryLocation,      // 分类后的内存位置
    pub destination_register: Option<String>,  // Load: 接收值的寄存器 (access=Write)
    pub source_register: Option<String>,       // Store: 提供值的寄存器 (access=Read)
    pub evidence_detail: String,       // 证据详情（指令地址、opcode、operand index、access、location）
}
```

### 4.2 destination/source register 推导规则

**基于结构化 OperandAccess，非"第一个 register"启发式：**

| kind | destination_register | source_register |
|------|---------------------|-----------------|
| Load | 同指令中 `access=Write\|ReadWrite` 的 Register operand | None |
| Store | None | 同指令中 `access=Read\|ReadWrite` 的 Register operand |
| ReadWrite | 同指令中 `access=Write\|ReadWrite` 的 Register | 同指令中 `access=Read\|ReadWrite` 的 Register |
| Unknown | None | None |

**示例验证：**

```asm
; mov rcx, [rsp+8]  —  Load
; RCX: access=Write  →  destination_register = Some("RCX")
; [rsp+8]: access=Read  →  kind=Load

; mov [rsp+8], rax  —  Store
; [rsp+8]: access=Write  →  kind=Store
; RAX: access=Read  →  source_register = Some("RAX")
```

## 5. analyze_function_memory() 规范入口

### 5.1 位置

从 `fox-analysis/src/pipeline.rs` 的 `mount_memory_analysis()` 移至 `fox-ir/src/memory.rs` 的 `analyze_function_memory()`。

### 5.2 签名

```rust
pub fn analyze_function_memory(ir: &IRFunction) -> MemoryAnalysis
```

### 5.3 执行流程

```
IRFunction
  ↓
for each basic_block:
  for each instruction:
    for each operand (with index):
      if IROperand::Memory:
        1. classify_memory() → MemoryLocation
        2. MemoryOperationKind::from_access(operand.access)
        3. 推导 destination_register / source_register（基于 OperandAccess）
        4. 构建 evidence_detail（instr addr, opcode, operand idx, access, location）
        5. analysis.add_operation()
  ↓
MemoryAnalysis
```

### 5.4 pipeline.rs 调用

```rust
// P0-4.2 (after)
let memory = Some(fox_ir::memory::analyze_function_memory(&ir));
```

删除了 65 行的 `mount_memory_analysis()` 实现。

## 6. MemoryLocation 保守分类（保持不变）

`classify_memory()` 在 P0-3.4 已建立，P0-4.2 **不修改其算法**，仅确认其保守性：

| 模式 | 分类 | 保守性 |
|------|------|--------|
| RIP-relative + effective_address | Global | ✅ 精确 |
| RSP/RBP/ESP/EBP/SP/BP + no index | Stack | ✅ 合理 |
| no base + no index (absolute) | Global | ✅ 合理 |
| base+index 或其他 base | Heap | ⚠️ 保守（可能是 stack with index，但不猜测） |
| 无法分类 | Unknown | ✅ 保守 |

**P0-4.2 测试验证：** `test_conservative_unknown_base` 确认 R12（非 RSP/RBP）被分类为 Heap，而非猜测为 Stack。

## 7. Evidence 链路

每个 MemoryOperation 携带：

```rust
pub evidence_detail: String
// 格式: "instr=0x{addr} op={mnemonic} operand_idx={i} access={access:?} location={location:?}"
```

**完整证据链：**

```
Machine Instruction (address)
    ↓
Structured IR Operand (IROperand::Memory with access)
    ↓
MemoryOperationKind (from_access, 非字符串解析)
    ↓
MemoryLocation (classify_memory, 保守分类)
    ↓
MemoryOperation (instruction_address + kind + location + destination/source + evidence_detail)
```

**P0-4.2 测试验证：** `test_evidence_chain` 确认每个 operation 有非零 instruction_address、非空 evidence_detail、且 detail 包含指令地址。

## 9. Architecture Changes

### Before (P0-4.1)

```
fox-analysis/pipeline.rs
  └── mount_memory_analysis()  ← 内存语义逻辑在这里（65行）
        ├── classify_memory()  ← 调用 fox-ir
        ├── is_load/is_store   ← 布尔标记
        └── data_register      ← "第一个 register" 启发式

fox-ir/memory.rs
  ├── MemoryLocation
  ├── MemoryOperation { is_load, is_store, data_register }  ← 布尔标记
  ├── MemoryAnalysis
  └── classify_memory()
```

### After (P0-4.2)

```
fox-ir/memory.rs  ← 内存语义逻辑的规范位置
  ├── MemoryOperationKind { Load, Store, ReadWrite, Unknown }  ← 语义枚举
  ├── MemoryOperation {
  │     instruction_address,
  │     kind,               ← 替代 is_load/is_store
  │     location,
  │     destination_register,  ← 基于 access=Write
  │     source_register,       ← 基于 access=Read
  │     evidence_detail,       ← 证据链
  │ }
  ├── MemoryAnalysis
  ├── classify_memory()     ← 不变（保守分类）
  └── analyze_function_memory()  ← 新规范入口（替代 mount_memory_analysis）

fox-analysis/pipeline.rs
  └── 调用 fox_ir::memory::analyze_function_memory(&ir)  ← 一行调用
```
