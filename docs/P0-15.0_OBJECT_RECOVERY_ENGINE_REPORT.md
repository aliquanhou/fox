## 2. 真实数据模型

```rust
pub struct FieldCandidate {
    offset: u64,
    accesses: usize,
    type_label: Option<String>,   // P0-13 未喂入，始终 None（fail-closed）
    touched_by: BTreeSet<u64>,
}
pub struct ObjectCandidate {
    id, base: u64, name: String,
    fields: BTreeMap<u64, FieldCandidate>,
    functions: BTreeSet<u64>,     // 跨函数共享证据
}
pub struct ObjectMap { objects, by_base }
```

### Pipeline（纯 analysis，不碰 emitter）
```
walk all statements:
  Assign{lhs=reg, rhs=Constant(global∈[0x460000,0x480000])}  → reg_to_base[reg_ver]=base
  Memory{address} / Binary{reg+const} / Load{address}
     └─ reg in reg_to_base  → record (base, offset) field access
  Pure Constant(global)                       → object itself
  ▼
aggregate by (base, offset): accesses + touched_by functions
```

### Query（Phase 6）
- `objects()` / `object_of_address(base)` / `fields_of_object(base)` / `field_at_offset(base,off)`
- `object_count()` / `total_fields()`

## 7. 已知 GAP

1. **字段覆盖窄**：objects=26 / fields=20，远少于 emitter 内部统计的 global_46E920（156 unique fields）。原因：本层只统计 structured **Expression 化**的 `reg+offset`；大量 `[reg+off]` 仍在 Unknown-reason 文本里（emitter 的 `try_parse_memory_operand` 解析），未接入本 analysis 层。**这是 P0-15 最大 GAP。**
2. offset 多为 0：`reg_to_base` 传播抓到 bare-pointer，但 `reg+offset` 的 Binary 形态在 structured IR 中稀少，导致 struct-layout（连续 offset）证据不足。
3. **类型未接**：FieldCandidate.type_label 始终 None；P0-13 FieldTypeFact 接口建了但 batch 传空（跨阶段累积 GAP）。
4. 字段 size 未恢复（指令宽度未知）。
5. 跨函数 object 共享只统计 functions 集合，未区分 create/update/query 生命周期。
