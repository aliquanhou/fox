# P0-5.5: Evidence → Claim Mapping Table

**Stage**: P0-5.5 Evidence Claim Layer Foundation
**Date**: 2026-09-10
**Commit**: c836d9d

This document is the canonical mapping from `EvidenceKind` to `EvidenceClaim`.
It is derived from P0-5.4 Architecture Audit and P0-5.3A Validation conclusions.

---

## Mapping Principles

1. **One Evidence may produce multiple Claims** (e.g., PdataEntry → Start + End)
2. **One Claim may be supported by multiple Evidence** (deduped by claim_type + subject)
3. **Evidence is not re-interpreted** — ValidFunctionBody never becomes FunctionStart
4. **Conservative mapping** — when in doubt, no default claim (empty vec)
5. **AddressTaken has no auto-claim** (per P0-5.3A: may be BB label)
6. **ReachableFromEntry = Reachability only** (per P0-5.3A: not FunctionStart)
7. **CFG evidence has no function-boundary claim** (BranchTarget, edges, etc.)

## Traceability

Every claim carries `source_evidence: EvidenceKind`, enabling:

```
Claim(FunctionStart @ 0x401000 [Supporting])
  ↓ source_evidence = CallReference { count: 3 }
  ↓ Evidence.address = 0x401000
  ↓ Instruction @ caller address → CALL 0x401000
```

No claim exists without a traceable source evidence.
